# Q6 / Q6+：最终问答奖励驱动的筛选器RL

用户2026-11-06明确要求新增RL版本，命名Q6及Q6+，并确认从Q5固定6轮SFT的适配器继续训练。Q6/Q6+共用一个策略和同一份keep证据，Q6+为主要结果。现有Q5评测和Q4的500题结果保持；新版本不因开始运行就自动替代Q4+默认基线。

实现入口为 `script/train_q6_rl.py`，策略及目标为 `script_core/q6_rl.py`。主实验使用原新增200题训练，固定6个epoch，每道题在每个epoch做两次独立完整Q4自适应流程，共1200组/2400条trajectory；结束后只用最终第6轮权重评测原300题。没有内部验证、选最佳轮或额外SFT重训。每轮末保存恢复检查点，不能据此按结果选轮。

## 训练内容

只更新原来56处语言注意力q/v上的LoRA（r8/alpha16、约252万参数）。视觉模块和底座参数冻结；仅`q3_filter`调用启用适配器。比较复核、针对性重判、导航、充分性判断及Q6/Q6+最终读者继续使用原底座。

筛选器仍读取原问题和原句观察/有限邻居，不读取选项、gold或reward。训练200题的gold独立保存于`train_rewards.json`，只在一条完整trajectory的最终答案落盘后用于计算奖励。没有新教师动作标签、没有把300题的答案作奖励或梯度目标。初始来源是原N已选观察和完整caption档案，后续独立导航、筛选、重判、补取和回答；不读取旧Q4/Q5预测来生成奖励或复制旧最终保留集合。

## 策略与优化

这是 **REINFORCE + leave-one-out基线**，没有critic，也没有PPO的多次复用/裁剪目标，不称为GRPO实现。参考思路：[REINFORCE-style LLM优化研究](https://arxiv.org/abs/2402.14740)；本实验的具体四类动作和奖励环境以代码为准。

每个观察选择direct/context/irrelevant/uncertain之一；前两者映射keep，后两者按原规则排除最终读者。四个标签的首token不同，策略在这四个token上归一化并采样，标签剩余token、原ID和JSON语法固定。各观察按同一个窗口中的既有前缀顺序条件化。这样只训练分类决策，不给任意格式噪声分配奖励。推理使用同一策略的argmax。此动作解码是Q6相对Q5的显式协议变化，不能宣称只换权重而所有解码逐字不变。

- 初始参数：Q5第6轮适配器；其冻结副本作为KL参考，只复制约10MiB适配器张量，不加载第二个7B模型。
- 行为策略：`0.9 * softmax(four_logits / 1.0) + 0.1 / 4`；优化重算完全相同的分布。语法与多token标签尾部没有独立随机概率。
- 奖励：只取Q6+最终答案，正确1、错误0；无删句、长度、选项教师标签或token奖励。Q6最终答案仍记录，作为对照而不进入奖励。
- 同题两条trajectory在同一策略版本下完成后才更新。`A_i = R_i - mean(other rewards)`，两条奖励相同时策略梯度为0，不伪造优势。
- 目标：`-sum_i A_i * sum_t log p(a_it|s_it) / (2*256) + 0.02 * mean KL(p || frozen_Q5_policy)`。256为固定尺度，不按单条轨迹长度重新加权。
- 一组只做一次优化器更新；所有窗口微批累积，重算时使用同一版本参数；没有跨更新复用旧rollout。首个有效奖励组检查有限非零LoRA梯度和底座无梯度，不做额外探针优化。
- AdamW只创建一次，lr5e-6、weight decay0、clip1；LoRA只挂载/载入一次。训练反向时关闭dropout以匹配行为策略，启用梯度检查点；底座bf16，适配器/优化器fp32。
- 前向KV缓存采样与完整因果重算逐动作比对，漂移大于0.05直接停，不静默换目标或忽略离策略问题。

## 来源、预算与成本

沿用完整Q4自适应流程、keep-only、针对性复核、最多补读4个caption场景、充分性早停、150秒工具配置、3600秒每trajectory预算及90秒双最终回答预留。训练内调用在同一模型进程执行，使用原生成器软deadline，且每个训练内层叶调用都有独立的进程终止watchdog；超时保留pending预约及hard_deadline_failure档案，停整个RL模型进程，不伪造reward。整个训练IPC另有外层硬超时。模型调用raw及每个动作的原始token序列、概率、选择、策略版本均落盘。整个trajectory及成本发布后才计算reward，真实工具错误停实验，不作为reward=0掩盖。

每条trajectory按原预算保守扣完整历史N来源依赖一次；统计中实际新rollout处理、梯度/参考前向及按训练题去重的历史来源成本分列，不把历史N依赖当作新GPU调用耗时。六轮RL含2400条完整问答路径，比单纯SFT的训练开销高，不能用SFT训练时长直接估算完成时间。300题是用户指定、已反复分析的开发验证集，不称未见holdout。
