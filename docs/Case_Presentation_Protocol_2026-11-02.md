# Case 展示规范

记录日期：2026-11-02（新加坡时间）。根据用户逐次补充的要求整理；以后展示 K/L/M 或后续版本的 case，默认遵循本规范。

核心要求：**以每条被选中帧的原始文本为主线，逐条展示处理前后，直到实际送入决策模型的文本。** 不能只展示最终摘要或筛选后的几条证据，让用户自行猜测中间变化。

## 用户逐步明确的展示要求

1. 首先给出原问题、全部选项、实体化的数据、进一步合并筛选后保留的数据，以及最后整合给决策模型的信息。
2. 在解释处理结果前，先展示具体选择了哪几帧，以及各帧各自的原始文本；再展示解构结果。
3. 说明视频分成多少个场景，每个场景从几秒到几秒。
4. 解释 `source_caption_ids`、`R1/R2` 等标识，明确它们指向什么，不能只摆内部编号。
5. 展示方式进一步确定为“每帧原始文本改动前后”：逐条追踪所有被选中的原始信息，说明各条信息处理到最后分别是什么样子；被跳过的也要列出。
6. 解释为什么选择这些场景，区分一开始打开的场景与后续逐轮扩展，不能把最终累计打开的三个场景说成一开始就同时选中三个。

## 每个 case 的展示顺序

### 1. 原题与运行来源

给出原问题、全部选项及选项编号，标明实验版本、实际运行目录与 case ID。说明展示来自真实保存调用还是模拟检查；不能混用 K、L、M 的不同来源。

如展示模型答案、正确答案和答对与否，将其作为结果单独列出；不要把正确答案混进证据处理链或选择理由。

### 2. 所有场景的总览与选择过程

列出所有场景的 ID、时间区间和各自总描述，再标明哪些实际打开、哪些未打开。区间统一用 `[起点,终点)`，明确单位为秒。
用户进一步要求：场景表必须同时展示每个场景的 summary，不能只列区间及是否读取。优先逐字引用实际保存的 summary；旧 summary 不可恢复时明确标注。若为帮助阅读而根据原 caption 新写概述，须单列为“本次依据原 caption 补写的概述”，不能冒充当时的模型 summary，也不能假装它参与过原运行。

有真实导航记录时，按轮次展示：当前场景、选择理由、检查结果、具体证据缺口、为什么当前场景无法补足、因此打开哪个下一场景，以及最终停止理由。

M 的过程按已确认的方法解释：**所有场景总描述 → 最相关的一个 → 细查当前场景 → 明确缺口 → 当前无法补足才打开下一个相关场景 → 足够即停止**，不强制时间覆盖。旧 K/L case 则解释当时实际使用的选择逻辑，不把 M 的新逻辑套到旧运行上。

原场景总描述或逐轮日志已丢失时，明确写“原记录不可恢复”。可以展示有依据的重建边界，但必须标为重建，写出依据；不得编造原总描述、初始选择、访问顺序或当时的模型理由。

### 3. 具体选帧与原始文本

按时间顺序列出全部已选帧／采样点、所在场景、时间区间、原始 caption，提供对应图片或图片链接。原文保留原样，包括来源标记和原有措辞；如另给清理后的文字，应独立成列。

区分“已有 caption 被读取”与“本次模型实际看了该图”。图片供人核对，不意味着规划器已经做过视觉核验。

### 4. 每帧处理前后对照

主表采用以下列，不只展示最终保留的帧：

| 帧／时间区间／场景 | 原始文本 | 实际解构结果 | 对应候选及处理 | 最终决策输入中的实际文本 |
| --- | --- | --- | --- | --- |
| 具体采样点 | 完整原文 | 已接受的实体／事实字段；或明确原文回退 | 候选 ID、保留／跳过／不确定／合并组 | 完整对应句段；没有进入则明确标记 |

解构列展示实际存储内容，不用事后重新抽取的“更好结果”替代。字段缺失、抽取失败、原文回退都应明确。内部结构可以展示 JSON，最终呈现列必须复制真实输入中的文本。

“对应候选及处理”不能只写“原文 R14 跳过；结构化句 R15 保留”等编号缩写。每行写清：原始 caption 是什么；原文清理后形成的完整候选句是什么；实际结构字段如何通过模板形成另一条完整候选句；每条句子的保留／跳过结果；最终模型接收哪句。说明编号只是候选标签，不是两帧，也不代表两次独立事件。多帧共同支持同一候选时列出来源，不能误说成只来自当前帧。解释为何这样选时区分实际保存理由和事后分析；无真实理由则明确未记录。

例如第12秒原文 `#C C holds the dog leash`：原文路径清理来源标记形成 R14 `C holds the dog leash.`；结构化动作 `{actor:C, verb:holds, patient:dog leash}` 经句子模板形成 R15 `C holds dog leash.`。K 将 R14 标为 skip、R15 标为 keep，因此最终保留“C拿着狗绳”这一事实的后一种表述，而非把该帧整条信息删掉。这里对12秒的 R15 描述的是其结构化来源；整个池中 R15 还汇集其他采样点的同文候选。实际规划没有逐条解释选择原因，不能断言模型就是为了去重才这样选。

直接 caption 候选和经上游时序／实体档案关联的候选分开标注。关联到同一帧，不表示该帧原文支持关联句段的全部细节。发现原文与派生陈述不一致、细节增加或错误关联时，直接指出。

### 5. 合并与筛选的可追溯性

列出筛选前候选、原始规划决策、保留项、跳过项与合并组；展示合并前后正文及其全部来源和时间。没有保存逐项理由时，只报告实际决策，不编造模型为何保留或跳过。

解释每类 ID 的命名空间，例如 caption 来源、当前题的候选编号、实体引用、关系编号。`source_caption_ids` 要能回查到具体时间和原文；`R1/R2` 等必须结合所在字段解释，不能假设所有 R 都是一种记录。组名也不代表自动加入同编号候选。

同一最终段落可能对应多个帧，因此逐帧表里可以重复列出以便追踪，但要说明它在实际完整输入中出现几次。不能把共享来源映射误说成重复输入，也不能把同段中的重复陈述隐去。

### 6. 实际最终决策输入

展示最终 Description 的完整正文，并提供实际 system、user 消息或完整聊天模板的文件链接。用户问“最终给决策模型的就是这段吗”时，直接核对原保存输入，说明该段是其中一部分还是全部。

区分证据正文、问题与选项、回答格式指令，以及解码器施加的外部约束。说明“实际发给模型的内容”，不能用概念示意或事后润色文本替代。

用户进一步要求精简时间呈现：后续 M 证据正文使用 `Frames` 替代 `At sampled intervals`，同一条陈述的相邻区间合并，例如 `[4,5), [5,6)` 显示成 `[4,6)`；跨空档的区间仍分开，不把不同陈述或不同证据性质混在一起。审计保留全部原始采样区间。这仅压缩显示，不证明动作连续发生了两秒。`source assertion` 表示来源文本中的陈述，未额外证明其真实或经过视觉核验；展示时用中文解释，不将其当作可信度结论。引用旧 K/L 或正在运行的冻结 M 输入仍保留原样；若演示新格式须明确标为重呈现，不冒充当时的实际输入。

聊天中可以先展开重点帧，但要注明节选，并链接所有已选帧的完整表和完整最终输入。JSON／CSV 可作补充，不能替代可直接阅读的前后对照。

最新呈现补充：用户明确认为逐句的 `(source assertion)` 无必要，后续 M 和新格式展示省略该默认标签，直接写 `Frames [4,6): C walks dog.`。来源性质保留在候选池与审计中；推断／未解决假设的区分标记仍保留。此条覆盖前文默认来源标签的显示方式，旧冻结输入不改写。

## 所有后续方案的导航记录保留要求

用户于2026-11-02针对“逐轮选择理由没有保存，无法还原为什么只读取某场景”的问题，明确要求后续所有方案都保存。此要求适用于 M 和之后所有版本，不限于挑出来展示的 case，也不只保存最终答错的题。

每题至少保留以下原始记录：

| 环节 | 必存内容 |
| --- | --- |
| 场景目录 | 每个场景的ID、区间、实际summary、caption来源及目录构建依据 |
| 初始选择 | 问题、全部选项、当时可选场景、选中场景和原始选择理由；程序排序则保存实际规则与分数 |
| 每轮检查 | 轮次与顺序、当前和此前打开的场景、实际读取的帧／caption引用、局部检查及抽取请求 |
| 缺口与扩展 | 尚缺的具体证据、当前场景为何无法补足、候选下一场景、选择的下一场景及理由、实际是否打开 |
| 决策校验 | 原始模型决定、选项对比及充分性核对、校验结果；程序修改或拒绝决定时保存原决定、修改后决定与程序原因 |
| 结束 | 实际停止原因：充分、无有用步骤、资源上限、无进展或失败；同时保留最终已打开场景和已读采样 |
| 调用溯源 | 模型原始输入输出、调用ID、顺序／时间、来源文件引用、版本与必要hash，能从最终答案回查到当时的选择过程 |

模型调用记录随调用落盘，不只在全题或全实验成功后保存。失败、中断时保留已产生的记录；后续展示引用当时保存的实际理由，不能根据正确答案或最终场景倒推一套理由。

M 的现有路径为：场景目录 `directory.json`；导航结果 `partial_search/result.json` 中的 `retrieval`（包含首场景理由和目录）与 `reviews`（包含逐轮理由、gap、当前场景判断及充分性核对）；调用账本 `partial_search/calls.jsonl`；对应原始输入输出 `partial_search/raw_calls/`。这些文件需要一起封存，只有最终回答或最终选中秒列表不足以恢复导航过程。

后续方案若直接复用已选证据、没有重新导航，要保存来源运行及原导航档案的关联。历史原导航确已缺失时，明确写“历史记录缺失，本版本未重做导航”，不得伪称补齐了原理由。新导航必须完整记录。

未来整理或清理工作目录时，默认保留上述可追溯档案，可以完整归档迁移，但不能只保留汇总分数后删除逐题导航记录。用户明确授权删除指定档案时遵从该授权，并明确记录被删除的范围。此要求不改写已冻结实验，也不将新记录倒填成旧运行的原始记录。

## M候选集流程补充（2026-11-02）

新版M先冻结候选集合。展示时先给全部场景的实际summary和每项candidate／excluded判定、模型优先级与原始理由，再展示程序实际队列及排序规则（候选内优先级降序，同分按原目录顺序）。名单不是事后根据最终答案重排的结果。逐轮标出下一允许候选和实际打开场景；候选耗尽、初筛无候选与资源提前耗尽分别记录。保存partial_search/navigation_trace.json及原始调用，不能只保留最终队列或汇总分数。初筛漏选／误选也要如实展示。
