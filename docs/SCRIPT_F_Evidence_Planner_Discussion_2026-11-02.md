## 1. 问题来源与目标

用户认为，当前已经获得的信息可能足以回答部分错题，但干扰信息和冗余信息被一并送入最终回答模型，可能降低效果。这是需要通过对照实验验证的假设，不能把所有错题都归因于冗余，也不能把减少输入直接等同于提高准确率。

此前 G＋GRPO 更新的是 Qwen 回答侧的 LoRA，G 记忆及证据选择固定。正式 300 题同运行时对照中，G 为 183/300（61%），G＋GRPO 为 180/300（60%），纠正 0 题、退步 3 题。该实验未体现收益，但不能据此认定独立证据选择训练也无效。历史训练权重和运行实现已按此前要求删除，不恢复。见 [G＋GRPO 实验记录](SCRIPT_G_RL_Experiment_2026-10-31.md)。

本轮目标是独立训练／适配一个小模型，结合问题与已有信息，规划哪些证据值得传递、哪些可以合并、哪些可以跳过。最终回答模型保持固定，以检验证据规划本身的作用。

最初讨论曾提出以 G 为基线，用户随后明确改为以按需版默认 F 为基础；后续工作按 F 定位，不改成 G 基线，也不自动采用 H/I/J 的方法。随后用户明确将该路线命名为 K。

## 2. 已核对的 F 当前行为

### 2.1 字段规划与内容筛选不同

F 当前字段规划器由原始 Qwen 配合提示词和约束输出实现，尚未针对本任务单独训练。其模型输入是问题、全部选项、可用字段列表及来源类型，不包含具体来源文本。用于缓存键的来源范围不等于规划模型已经读过这些证据。

例如，规划器可以请求 `actions.base`、`actions.instrument`、`actions.material`。程序保证基础动作字段存在；来源抽取器随后接收单条来源和所需字段，不看问题、选项或正确答案。

因此，当前规划器决定的是“抽哪些类别／字段”，不能等同于对具体事实的价值判断。用户指出：只看任务而不看已有信息，无法充分判断真正需要哪些内容；后续规划应把问题和已有证据一起看，而不是把问题驱动的字段选择作为唯一筛选入口。

### 2.2 F 不是完整统一实体图

F 保存按来源和字段组织的动作、属性、状态、实体关系、变化、结果和事件联系，并支持增量抽取与缓存复用。内部字段可以表达实体参与的事实，但这不代表所有对象都已具有跨时间、跨场景统一且可靠的物理身份。

F 本身没有套用 E 的实体时间线呈现。最终提示中已有的 `Temporal entity memory` 来自上游流程，不能误说成 F 新建立的全局实体图。F 原有固定维度状态 schema 与 G/H 的开放状态设计也应分开说明。

### 2.3 来源保留与混合呈现

上游选定证据范围并交给 F 后，F 保留该范围内每个采样点。抽取、缓存复用、句子化不会按价值删除采样点；上游仍在探索时可以增加采样点，不同问题也可以有不同范围。

只有抽取事实通过完整句子覆盖检查，才用事实替换该条来源的原文；抽取不完整、不确定或失败时保留完整原文。渲染时原文优先，不再重复展示同一来源的衍生字段。

真实例子：

| 时间 | 原始描述 | F 的处理 |
| --- | --- | --- |
| `[135,136)` | `#C C moves the craft papers on the table` | 动作骨架未覆盖“桌上”，呈现原文 |
| `[136,137)` | `#C C moves a paper on the table` | 动作骨架未覆盖“桌上”，呈现原文 |
| `[137,138)` | `#C C picks the carton paper` | 动作事实通过完整覆盖检查，可呈现为句子 |
| `[138,139)` | `#C C moves the ruler on the table with his left hand` | 动作骨架未覆盖“桌上”和“左手”，呈现原文 |

这说明 F 即使只抽取部分字段，也不一定缩短最终输入：原文回退仍保留了其他内容。未请求某字段不等于获准删除对应信息。

F 当前最终输入由任务指令、替换后的 `Description`、问题与全部选项、上游时序实体记忆及已有视觉补充组成。只在 `Description` 或结构化字段上筛选，会漏掉其他区域的重复／干扰信息。

## 3. 已确认的任务方向

| 方面 | 讨论中确认的要求 |
| --- | --- |
| 基础方案 | 按需版默认 F |
| 模块职责 | 独立小模型负责证据规划；最终回答模型固定 |
| 规划依据 | 联合读取问题、全部选项和当前已经获得的信息 |
| 候选范围 | 结构化事实、保留原文、上游实体时序记忆、已有视觉观察；保留各自来源性质 |
| 筛选粒度 | 同时考虑采样点是否必要，以及采样点内哪些具体事实需要保留 |
| 判断依据 | 对区分选项的贡献、相对已选证据的新增价值、重复程度、互补关系及必要上下文 |
| 合并 | 区分“没有价值”和“有价值但可合并”；减少重复正文，同时保留来源与时间 |
| 呈现 | 内部可使用结构化存储和规划，最终证据通过完整句子表达，不直出字段串 |
| 模型大小 | 长期希望模型较小；首轮用户明确先复用现有 Qwen2.5-VL-7B-Instruct 验证功能 |
| 推进顺序 | 可以先直接复用现成模型建立未经本任务专项训练的基线，再根据反馈训练 |

这不是单纯换一种相似度排序，也不要求先将全部视频重建成统一知识图谱。候选首先来自当前已经获得的信息；是否扩展检索或新增视频观测尚未讨论定案。

## 4. 保留、合并与跳过的语义

下面是讨论中的概念动作，并非已经确定的接口或输出 schema。

| 判断 | 含义与处理 |
| --- | --- |
| 保留 | 提供独立贡献，或是理解其他证据必需的上下文 |
| 合并 | 内容有用，但正文与其他证据重复，或者可以共同组织为一段而不丢失各自事实 |
| 跳过 | 对当前任务及当前已选集合没有足够的新增价值，不继续送给本次回答模型 |
| 暂不确定 | 尚不能可靠判断价值或合并条件，讨论中倾向先保留 |

跳过不等于删除记忆库的原始记录，也不等于该信息对所有未来问题都无用。候选集合或问题变化后可以重新判断。

例如：

```text
[10,11) C 拿着抹布。
[15,16) C 拿着抹布。
```

可以考虑合并正文为：

```text
在 [10,11)、[15,16) 的采样中，C 拿着抹布。
```

必须保留两次观测，不能据此改写成“C 在整个期间一直拿着抹布”。同样，动作重复采样不直接证明动作次数；计数、先后和状态变化题可能需要这些离散记录。

“拿起抹布”和“用抹布擦桌面”表达不同动作，即使涉及同一实体，也不能直接去重。它们可在保持事实区别的前提下组织为一段话。“桌面原来有水”与“擦拭后桌面变干”则可能互相补充，不能只按每条单独的相关性决定去留。

相近名称不保证同一物体，相似措辞不保证同义；同义归一、跨来源身份合并以及时间区间合并的具体规则均待定。

## 5. 候选实现流程

```text
F 当前已经获得的信息
原始描述＋结构化事实＋实体时序记忆＋视觉观察
                         ＋
                    问题和全部选项
                         ↓
                  独立小模型规划
                         ↓
             保留／合并／跳过／暂不确定
                         ↓
              程序校验、执行选择和分组
                         ↓
                 完整句子的证据输入
                         ↓
                  固定的最终回答模型
```

候选工程思路是为证据分配稳定 ID，记录原文、事实、时间、来源以及不同区域之间的对应关系；让小模型输出引用这些 ID 的内部计划，再由程序检查来源、范围和合并结果，组织最终句子。模型不应通过生成新措辞偷偷补入未知事实。

同一内容可能出现在 Description、时序记忆和视觉补充中，需要能发现这些重叠，同时保留不同来源的证据身份与不确定性。规划应针对整个最终证据输入，而不是筛完一处后，在其他区域继续重复传递同一内容。

原问题驱动字段规划器是否取消、改为证据感知规划、还是保留在其他位置，尚未定案；只要继续使用，就不能让未被它请求的字段及其原文对后续内容规划不可见。

## 6. 小模型与训练：已经讨论的选项

### 6.1 先直接复用

“未训练基线”指复用已有预训练／指令模型，尚未进行本任务专项训练，不是随机初始化模型。模型要能理解联合输入，并执行保留、合并、跳过的规划。

讨论中曾建议 Qwen3-0.6B 作为较小的直接复用候选；用户随后决定先使用本地现成的 `Qwen2.5-VL-7B-Instruct`，不采用该 0.6B 候选作为首轮模型，也不需要为首轮下载另一套权重。

首轮规划器与现有 F 字段规划／抽取及最终回答模型使用相同基础型号，但职责不同：新规划器要联合读取问题、选项和当前已有证据，规划保留、合并与跳过，不只是输出字段名。独立规划接口尚未接入，不能把既有 F 字段规划调用当作新功能已经完成。

2026-11-02 对本地 5 份 safetensors 仅读取文件头和文件大小，未加载模型：总参数 8,292,166,656（约 8.29B），其中语言及其他部分 7,615,616,512，视觉部分 676,550,144；权重文件共 16,584,414,560 字节，约 16.58 GB／15.45 GiB。这是权重文件大小，不是含激活、KV cache 或训练优化器状态的总显存需求。模型官方说明见 [Qwen2.5-VL-7B-Instruct](https://huggingface.co/Qwen/Qwen2.5-VL-7B-Instruct)。

### 6.2 更小的专用模型

此前讨论过几千万参数文本编码器加轻量选择头／证据交互层的思路。例如 BGE-small-en-v1.5 为约 3340 万参数、512 token 单次输入的英文编码器，可作为候选底座，但它自身不是已经具备本任务规划能力的模型，增加的选择模块需要训练。相关规格见 [BGE 官方说明](https://bge-model.com/tutorial/1_Embedding/1.2.1.html)。

分条编码不能直接解决跨证据的重复与互补判断，还需要证据交互或结合已选集合重评分。讨论中曾提出约 3000 万至 4000 万参数的专用选择器作为规模设想，这不是用户已经确认的硬性目标或已实现模型。

当前决定先验证现有 7B 型号的直接复用效果。训练或蒸馏到更小专用模型仍是后续候选，尚未确定；首轮选择相同 7B 型号不构成模型规模缩小，也不能预先宣称规划开销较低。

### 6.3 训练反馈与可能的阶段

讨论过先监督适配、再视需要使用 RL 的路线。反馈可以来自训练题上固定回答模型的证据增删和组合对照：加入后是否纠错、删除后是否退步、合并后是否仍答对、不同证据组合是否互补。正确选项相对其他选项的分数变化也可作为候选辅助信号。

用户进一步明确，后续可单独初始化一份 `Qwen2.5-VL-7B-Instruct` 用于 fine-tune。这里是从已有预训练／指令权重初始化独立规划器，不是随机权重从零训练；规划器训练产物与版本应独立，最终回答模型继续保持原始固定权重。使用全参数微调还是 LoRA、具体监督目标或 RL 算法尚未确定；本轮不恢复旧 G＋GRPO 适配器。

这些反馈反映证据对当前回答模型的帮助，并非证据客观真假的证明。小模型自身生成的计划和解释不能直接充当正确标签。

正确答案只能在训练反馈和评估环节使用，不能作为运行时规划器的输入。同题产生多组子集也不能冒充多道独立训练题。训练／验证划分、视频来源重叠、检查点选择及奖励设计尚未定案；不能自动沿用此前 G＋GRPO 的 200/300 协议启动新训练。

后续若引入长度或成本惩罚，应以答题质量为主要目标，防止模型为了少选信息而漏掉关键证据。权重、损失、优化器及 RL 算法均未确定。

可参考用最终任务反馈训练独立上下文压缩／筛选器的研究：[RECOMP](https://arxiv.org/abs/2310.04408)、[FILCO](https://arxiv.org/abs/2311.08377)。这些参考不代表其方法已经适配或验证于当前 F。

## 7. 候选验证方式

首先比较当前 F 与“F＋未经专项训练的小模型规划”，固定题目、候选证据范围、最终回答模型、选项顺序、生成和解析协议。可增加相同输入预算的相似度筛选与随机筛选，区分学习到的信息选择收益和单纯输入缩短的影响。

需要记录：

- 正确率、同题纠正／退步及实际完成分母；
- 最终输入 token、规划耗时与最终回答耗时，规划开销不能隐藏；
- 保留／跳过的采样点及具体内容、合并组与来源映射；
- 关键证据误删、不同事件误合并、时间顺序和次数信息丢失；
- 无法可靠规划或合并时的处理，以及被跳过信息是否从其他区域再次进入输入。

减少 token 不是单独的成功标准。需要同时观察答题效果和新增规划成本。现阶段没有该筛选器的效果数据。
