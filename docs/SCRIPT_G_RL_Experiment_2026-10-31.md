## 固定 G，只训练回答适配器

G 的版本仍为 `generalized-entities-G-300-20261030-r3`。本轮不改变记忆分类、开放状态字段、角色规则、身份关联窗口、时间组织或来源保留。

200 题的上游证据来自 `full-temporal-videotree-500-20261027-r1` 已封存的实际 QA 输入、已选描述、旧时序记忆与已接受视觉观察。`memory200/` 复制原 G r3 的运行时、抽取控制代码和模型指纹，按原串行路径逐来源抽取；每题仍为 1500 秒预算、45 秒回答预留，局部身份窗口 8 秒、状态采样间隙上限 2 秒，原文保留与至多一次角色复核不变。这里仅构建 G 记忆，不生成训练集的最终 QA 答案。

原 300 题复用当前原 G 正式评测逐题封存的记忆输入，不以 D/E/F 的抽取替代。后台会等待原 G 完成后封存评估输入；原 G 任务保持运行。

回答模型为同一份 Qwen2.5-VL-7B-Instruct，bfloat16、SDPA。只更新语言模型 `q_proj` 和 `v_proj` 的 LoRA，基础权重及视觉模块冻结。新环境 `workdirs/g-rl-env/` 复用原推理依赖，仅安装 PEFT 0.17.1，不修改原推理环境。

## 预先固定的训练设置

| 项目 | 设置 |
|---|---|
| 算法 | GRPO，无 critic；每组一次 PPO 更新 |
| 数据 | 全部额外 200 题，一轮，seed 0 打乱顺序 |
| 每题采样 | 4 个回答，temperature 1、top-p 1、top-k 0 |
| LoRA | rank 8，alpha 16，dropout 0 |
| 学习率 | 2e-5，AdamW，无 weight decay |
| KL 系数／PPO 裁剪 | 0.02／0.2 |
| 梯度范数上限 | 1.0 |
| 生成上限 | 沿用原 QA 的 1024 token，不裁剪输入 |
| 奖励 | 正确 1，错误 0；无法明确解析或未正常终止为 −0.1 |
| 同组奖励相同 | 保存所有输出，跳过更新，不额外重采样 |
| 检查点 | 固定最终检查点，不按评估集挑选 |

每条采样输出和 token ID、奖励、解析、优势、损失、KL 与梯度范数均记录。报告有效优化步数和参数实际变化；没有有效更新则停止，不能宣称完成 RL 学习。

## 最终比较

在原 300 题上生成新 G＋RL 回答，并在同一运行时、相同输入和贪心生成设置下生成关闭适配器的 G 对照，按题交替两组顺序。两组统一采用独立的、无需正确标签的解析器：明确字母声明或唯一完整选项匹配；人物 C 的句子不作为选项字母。

此新协议的 G 对照与历史 G 原始响应另行核对。历史冻结预测及其主评分不覆盖，新报告不混用旧解析分数。

最终报告包含 G 与 G＋RL 的 300 题准确率、配对纠正/退步、格式错误、输入 token 和回答耗时，并单列新 200 题 G 记忆构建、模型加载、RL 训练及评估成本。继承的 G300 抽取仍是复用依赖，不宣称免费。

## 调度与失败处理

控制器按“训练 200 题记忆构建 → RL 训练 → 等待原 G300 完成 → 原 300 题配对评估”执行。每个 GPU 阶段启动前，任一卡连续三次观测至少 32768 MiB 空闲才启动，优先 GPU 3，允许共享，不停止其他任务。

r3 的记忆阶段由 `script/parallel_g_rl_memories.py` 调度四个分片进程，允许 GPU 0–3，每卡最多两个新增抽取进程，至少间隔 30 秒启动。启动条件仍为连续三次观测有至少 32768 MiB 空闲显存。GPU 1、2 当前有其他训练进程，显存不足时不放入新任务。分片完成后释放模型，再进入原固定 RL 训练与评估阶段。显存状态、各分片日志和进度保存于 `memory200/parallel/`。并发会影响逐调用耗时和预算消耗，因此耗时与预算回退须按实际记录解读。

训练和评估过程不自动重试、不静默量化、不裁剪上下文、不改用其他记忆或答案兜底。失败保留输出、账本和诊断后停止。共享 GPU 耗时仅作观测，不解释为受控速度增益。
