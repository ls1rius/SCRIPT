# 方案 P：继承 O，直接使用原始问题

2026-11-03，用户明确“弄成方案P，方案P继承自方案O”。版本：`P-O-direct-original-question-v1`。

P 的流程为：原句 → O 的独立单句抽取 → 原始问题 + 当前原句 + 全部抽取候选 → 0/1 筛选 → O 的结构化呈现 → 原始问题和全部选项下的最终回答。

与 O 的差别是取消 `o_filter_plan`，不生成、不传递 `evidence_task`。筛选只接受 `question`、`sentence`、`candidates` 三个字段；直接保留问题原文，不产生新的子问题或动作要求。单次相关观察不必独立证明反复、协调、整体过程或目的，这些要求写入固定筛选提示。此改动包含删除动态说明及相应固定提示调整，不能宣称只删除一个输入字段、其余提示逐字不变。

P 继承 O 的抽取提示/类别/schema、候选构建、整数 0/1 输出、保留动作时已抽出的主语/对象依赖、原句回退、结构化呈现、完整选项最终读者及预算/失败停策略。P 不包含 O+ 重组，也没有在本轮新增 P+。筛选不读选项，最终回答读全部选项。不重新导航、不训练、不生成 adapter，不接普通 `query --memory P`。

实现：

- `script_core/p_sentence_filter.py`：P 的固定提示与严格输入合同。
- `script_core/o_batch_generation.py`：复用独立 tensor 批处理，引入单独的 `p_filter` 分支，最多 4 条，同题/同条件、独立提示/attention mask/JSON 约束。
- `script_core/backend.py`：独立 `p_independent_batch`、`p_answer` 调用；O 外层调用不能混入 P 筛选。
- `script/run_p_sentence_experiment.py`：独立准备、排卡、执行、报告；保存全部原始调用、逐句抽取/候选/理由/标签/依赖覆盖、最终输入及成本。可重新抽取，也可冻结复用 O 的抽取进行受控比较；绝不复用 O 的筛选标签或答案作为 P 的新结果。
