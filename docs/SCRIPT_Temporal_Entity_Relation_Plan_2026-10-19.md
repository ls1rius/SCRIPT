本方案以时间连续的场景簇组织视频，以簇中心特征定位场景；进入场景后，为每个可观察实体建立属性档案，再建立包含状态持续时间、变化动作和实体关系的时序网络。查询围绕实体信息展开，跨场景时先对齐实体身份，再接入新的状态和关系，同时保留历史。

## 已确认的设计约束

| 环节 | 必须保留的约束 |
| --- | --- |
| 场景聚类 | 每个簇对应唯一、连续的时间区间；不把不相邻时段合成一个簇 |
| 场景顺序 | 保留原始视频时间，簇按时间排列，进一步细分也保持连续 |
| 簇表示 | 保存簇中心检索特征、按中心相似度排列的帧、原始时序和整簇描述 |
| 场景连接 | 相似或相关簇可用指针双向访问，时间邻接与相似跳转分别表达 |
| 实体档案 | 在已展开的簇中，为每个可观察实体记录可获取的结构、纹理、外观、颜色等信息 |
| 状态生成 | 初次观察建立初始已知状态；之后只有有依据的状态变化才产生新状态 |
| 状态时间 | 记录每个状态从几秒持续到几秒，边界不清时保留时间范围或未知 |
| 变化原因 | 连接前后状态，记录导致变化的具体动作操作、执行者、工具、时间和证据 |
| 实体关系 | 每个状态关联当时成立的关系，关系也有自己的有效时间 |
| 查询入口 | 根据实体属性、状态、关系和时间检索已有记忆 |
| 跨场景更新 | 先对齐同一实体，再延续或新增状态、挂接变化事件、更新关系的有效时间 |
| 原始资料 | 保留原始描述、帧与视频引用，结构化信息均可追溯 |

“重点保存状态改变”约束的是状态序列和变化连接的构建标准，不意味着省略其他实体或静态属性。外观和纹理等属性也是实体检索与跨场景身份对齐的重要依据。

## 整体流程

初始建库负责组织场景和定位材料，复杂实体网络在进入场景后建立。已经建立且来源未变的记忆可以复用；未展开场景通过目录定位后再建立网络。

```text
视频与已有描述
    ↓
抽帧和视觉特征
    ↓
带时间连续约束的场景聚类
    ↓
初始目录
  簇中心特征／帧的代表性排序／原始时序／整簇描述／场景指针
    ↓
查询定位相关场景或已有实体
    ↓
打开场景，读取原始材料，建立每个可观察实体的属性档案
    ↓
建立实体状态、有效时间、关系和变化动作
    ↓
检查问题所需的信息缺口
    ├─ 需要其他场景：沿指针访问 → 实体身份对齐 → 接入新的时序关系
    ├─ 需要视觉细节：定位局部视频 → 补充观察或核验
    └─ 信息足够或预算用尽：最终回答，同时保留证据充分性状态
```

## 连续场景聚类

### 场景区间

场景簇是连续视频区间，按原始时间依次覆盖允许处理的范围。可用半开区间 `[start_seconds, end_seconds)` 表示，避免两个相邻区间在边界上重复归属。

例如：

| 场景 | 时间区间 | 内容示例 |
| --- | --- | --- |
| S1 | 0–20 秒 | 厨房准备材料 |
| S2 | 20–40 秒 | 在另一处操作台处理材料 |
| S3 | 40–60 秒 | 回到厨房继续加工 |

S1 与 S3 即使视觉相似，也保持为两个簇。它们可以建立相似指针，不能合并成一个跨越 S2 的场景。读取失败或资料缺失的区间须显式记录，不能伪造完整观察覆盖。

### 视觉特征与切分

复用已有视觉特征，使用时间连续约束决定分段边界。当前代码中的 `contiguous_partition` 和原始帧边界映射可作为实现基础；分段惩罚、最短和最长区间等参数需要单独验证。

原 VideoTree 的无时间约束相似性聚类保留为历史基线。新方案可复用其特征、模型和其他工具，但场景划分必须满足连续性；后续层级细分也只能在父区间内连续切分。

## 每个场景簇的表示

| 内容 | 保存方式与用途 |
| --- | --- |
| 时间范围 | 场景起止秒数、原始帧范围 |
| 成员资料 | 簇内全部合法帧引用、原始描述和时间 |
| 簇中心特征 | 场景的主要检索表示，记录所用编码器和特征版本 |
| 代表性排序 | 按帧与簇中心的相似度从高到低排列 |
| 原始时序 | 独立保存时间排序，用于动作过程、状态变化和时间查询 |
| 整体描述 | 概括整个簇的活动、实体、工具及关键变化，并保留来源引用 |
| 场景指针 | 时间邻接、相似跳转及其目标和关联线索 |
| 展开状态 | 尚未建立实体网络、部分建立或已建立，以及材料覆盖范围 |

中心特征可由簇内帧特征聚合获得。若采用余弦相似度，归一化帧特征求均值后再归一化是一种实现选择；具体聚合方式和距离度量尚需固定并验证。

按中心排序用于寻找代表帧，按时间排序用于理解过程，两套索引同时保留。生成整体描述时须综合整个连续区间，不能用中心帧的一条描述代替整簇内容。代表性较低但包含重要状态变化的边界片段仍需被读取和保留。

### 检索特征空间

主场景检索表示固定为簇中心特征。图像查询可以使用同一视觉编码器；文字问题需要通过兼容的跨模态编码或经过验证的映射进入可比较的空间。现有 BGE 文本向量不能直接与视觉簇中心计算相似度。

文字查询如何进入该空间是待实现验证的接口，不能以描述文本向量悄悄替换簇中心。场景描述可以提供辅助关键词和解释，但其用途须与中心特征检索分别记录。

## 场景之间的导航指针

目录保留时间顺序指针，并在相似或相关场景之间建立可双向访问的导航指针。例如 `S1 → S2 → S3` 表示时间顺序，`S1 ↔ S3` 表示可以直接跳转查询相关内容。

指针中的“下一个场景”是下一处访问位置，可能不是时间上紧邻的场景。指针至少保存源场景、目标场景、连接类型、关联线索和时间方向；相似指针可另存中心相似度。

初始指针负责导航，不自动证明两个场景中的物体相同，也不代表两个场景间存在已确认的因果或操作过程。具体实体对应在实际访问场景后建立。

## 实体属性档案

进入场景建立复杂关系时，应覆盖该场景中每个可观察、可辨认的实体。主体、工具、材料、容器、相关部件等都可以成为实体；不能只为当前猜测答案中的对象建档。

每条属性记录保留值、观察时间、来源和确定程度。可获取信息包括：

| 属性类别 | 示例 |
| --- | --- |
| 结构和组成 | 部件、连接、开口、把手、整体与组成部分 |
| 形状和几何 | 轮廓、尺寸线索、相对大小 |
| 纹理和表面 | 纹路、图案、表面粗糙程度等可观察特征 |
| 外观和颜色 | 颜色、标记、可辨认图案及外观特征 |
| 材料 | 有依据的材质或材料类别 |
| 空间和姿态 | 位置、方向、姿态、遮挡和可见区域 |

这些类别是开放属性集合的示例，不表示每个实体都能获得全部属性。未知或不可见的信息保持未知，并记录覆盖情况。

同一实体有稳定身份，场景中的局部实体 ID 映射到该身份。补看另一个侧面、获得更清晰纹理或补充颜色观测，可以丰富档案；仅增加知识不自动产生新的物理状态。光照、视角与识别噪声也需要与真实属性变化区分。

## 实体状态序列

### 产生新状态的条件

初次观察建立初始已知状态。之后，出现有依据的属性、位置、持有者、开闭、连接、组成或材料形态变化时，才建立新状态。关系变化也可能构成状态变化，例如从“位于桌面”变为“被人物持有”。

重复观察同一状态时延续记录，不逐帧生成状态。场景边界本身也不产生新状态：身份明确且在相邻场景中持续可见的同一实体，可以延续已有状态。

实体回到曾经出现过的状态时，需要记录新的时间段。例如“桌上 → 手中 → 桌上”的最后一个状态是新的状态实例，不能与最初的“桌上”合并成一个持续区间。

### 状态记录

| 字段 | 含义 |
| --- | --- |
| `state_id` | 这个状态实例的标识 |
| `entity_id` | 所属实体的稳定标识或待确认身份 |
| `properties` | 该状态下已知的属性及其引用 |
| `valid_from`、`valid_to` | 有来源支持的起止秒数；未知边界允许为空 |
| `start_bounds`、`end_bounds` | 边界只能确定在某个时间范围内时的记录 |
| `first_observed_at`、`last_observed_at` | 实际首次与末次观察时间，与持续时间分开 |
| `supported_intervals` | 状态得到观察支持的区间，便于明确观察空档 |
| `relation_refs` | 该状态下成立的实体关系 |
| `evidence_refs`、`status` | 来源以及描述线索、待核验解释或视觉支持等状态 |
| `end_reason` | 状态变化、视频范围结束、失去观察或尚未结束等 |

字段名称是实现建议，状态必须具有有效时间和来源是已确认要求。

### 时间边界

状态持续时间、动作操作时间和描述引用区间是不同概念。一次操作可能持续数秒，某个状态也可能跨越多个场景，不能把动作区间或一段描述的跨度直接当作状态持续区间。

若在第 8 秒仍观察到旧状态，第 10 秒观察到新状态，实际变化边界只能确定在这段时间内；不能未经依据就填写精确变化时刻。

观察空档不会自动证明状态一直未变。可以保存最后已知状态及连续性假设，但与确实观察支持的区间分开。视频观测范围结束也不意味着实体在那一刻发生了新的变化。

## 连接状态的动作操作

每次变化通过一个事件连接前态与后态。事件记录变化是什么，以及什么动作操作造成了变化。

| 字段 | 含义 |
| --- | --- |
| `transition_id` | 变化事件标识 |
| `before_state_refs`、`after_state_refs` | 受影响实体的前后状态引用 |
| `action` | 拿起、放入、打开、切割、组装等具体操作 |
| `actor_refs`、`object_refs`、`tool_refs` | 执行者、作用对象和工具 |
| `action_interval` | 操作发生的原始视频时间区间 |
| `change_bounds` | 变化边界的确定范围 |
| `cause_support` | 该操作导致变化的依据和确定程度 |
| `evidence_refs` | 支持前态、操作和后态的描述、帧或视频来源 |

一次操作可以改变多个实体，因此事件可以连接多组前后状态。未发生变化的实体不因同一次观察而统一生成新状态。

原因字段落到具体动作及其证据上。只有前后状态而没有观察到操作时，可以连接状态并记录原因未知或待核验；时间先后本身不证明因果。仅出现“清洗”“修理”等描述，也不能据此补出“已经洗净”“已经修好”的后态。

## 每个状态对应的实体关系

每个状态关联在那段时间内成立的关系，如位于、接触、包含、被持有、连接、组成等。关系记录主体、对象、适用的状态引用、有效起止时间和证据。

实体档案提供身份和属性；状态记录一个时间段内的情况；关系边连接该时间段中的实体或状态；变化事件连接前后状态。四者共同构成时序实体关系网络。

关系的时间必须与相关状态及来源兼容。“杯子位于桌面”结束后，历史关系仍可回查；新状态中的“杯子被人物持有”从有依据的时间开始生效。

实现可以共享不变属性和关系，只保存变化增量，避免为每个状态复制整张图。查询某个已支持时间点时，应能恢复该实体当时的状态和关系集合。

## 查询与场景展开

查询从实体属性、状态、时间条件和关系条件中提取检索要求。例如“第 12 秒那只白色有柄杯子在谁手里”，包含实体属性、时间点和持有关系。

对于已经建立的记忆，先查实体档案，再定位相关状态和关系。属性本身可能发生变化，因此带时间的问题要匹配相应时段的属性，不能始终使用最新外观。

对于尚未展开的场景，先通过目录和簇中心定位候选场景，进入后读取原始材料、建立实体档案及网络，再执行实体查询。初始目录提供位置线索，不声称已经拥有全视频每个实体的完整关系。

查询过程中需要保留具体缺口，例如“已找到托盘中的小面块，但尚不清楚它们来源于哪块材料”。缺口决定下一次场景导航或局部补看的位置。

全局活动、计数、首次、末次和否定问题还需要相应的时间覆盖。单个局部状态或模型自信不能代替覆盖检查。预算耗尽仍可回答，但必须保留未解决缺口和证据不足状态。

## 跨场景身份对齐与关系转移

### 实体对应

进入另一个场景后，先比较两边的实体档案，综合结构、纹理、外观、颜色、时空衔接、动作连续性及竞争对象等依据，判断哪些实体属于同一个。

只靠同名、同颜色或同一地点不足以确认身份。对应不确定时保留候选或独立身份；有依据确认后，才把两边的局部记录挂到共同实体身份下，并保留各自原始来源。

### 时序网络更新

1. 对齐局部实体与共同身份。
2. 按原始视频时间插入新观察，不能按查询访问顺序排列历史。
3. 状态没有变化且连续性有支持时，延续已有状态。
4. 发生变化时，建立新状态和变化事件，记录操作及其原因依据。
5. 为新状态建立相应关系，结束已经被变化取代的关系。
6. 保留旧状态、旧关系和原始来源，支持历史查询及纠正。

“关系转移”指身份对齐后接入新的时序关系，不是把旧场景的关系无时间区别地搬到新场景，也不是用新关系覆盖所有历史。若查询先访问后面的场景、再回查准备阶段，网络仍按视频时间组织。

观察空档内是否发生其他变化可以保持未知。身份或状态出现冲突时，保留来源和待解决项，允许撤销或修正先前对应。

### 拆分和组装

材料被分割产生多个部分时，为产生的部分建立实体，保留来源关系；多个部件组成整体时，保留部件、整体及组成关系。不能把所有部分强行归为原实体的同一个 ID。

可用关系包括同一实例、不同实例、来源于、组成部分、组装进入和未知。身份延续与材料来源是不同的关系，均需来源支持。

## 局部视觉读取与证据

建立实体外观和状态时，应读取簇内可用的原始描述与必要帧或视频片段。描述没有提供颜色、纹理或结构的信息时，不能仅凭动作名称补出这些属性。

需要确定变化过程、实体对应或操作结果时，围绕缺口读取局部视频。支持完整变化通常需要相关前态、过程和后态；单帧只能支持其中可观察到的内容。

描述线索、文本推断和视觉支持分别记录。模型提出的候选、问题中的前提和选项内容不能自动写成已观察事实；未知关系也不能当作关系不存在。

所有结构回指原始描述、帧与视频时间，支持检查“这个属性如何得到”“状态从何时开始”“是什么操作导致变化”。

## 贯穿示例

以下是假设原始材料充分支持的示例。场景 S1 为 0–12 秒，S2 为 12–22 秒，两个场景各自连续。

实体 E1 的档案记录白色、有把手、相应纹理与结构及来源。人物、桌面和盒子也分别建立实体档案。

| 杯子状态 | 时间 | 关系 |
| --- | --- | --- |
| E1 S0 | 0–8 秒 | 杯子位于桌面 |
| E1 S1 | 8–15 秒 | 杯子被人物 C 持有 |
| E1 S2 | 15–22 秒 | 杯子位于盒内，22 秒为观测范围结束 |

```text
E1 S0 [0,8)
    └─ 8 秒 人物 C 拿起杯子 → E1 S1 [8,15)
                                    └─ 15 秒 人物 C 将杯子放入盒中 → E1 S2 [15,22)
```

E1 的状态 S1 跨越两个场景。进入第二个场景并对齐为同一杯子后，不因 12 秒的场景边界新建状态。到 15 秒发生放入操作时才建立新状态，同时结束持有关系、开始盒内关系。

查询第 12 秒的位置时，定位到 E1 S1 及人物持有关系；查询进入盒子的时间和原因时，读取 15 秒的变化事件及其操作来源。若实际资料只能把变化定位在 14–16 秒，则记录这个范围，而不是沿用示例中的精确时刻。

## 持久化与成本

可复用的场景、实体档案和有来源的状态关系保存到记忆层。本题的候选答案、临时缺口和待验证对应单独记录，避免把一次查询中的猜测永久写成事实。

重复处理同一来源不应重复生成实体、状态和变化事件。原始资料、特征或模型版本改变时，需要检查对应记忆是否仍可复用。

模型输入通过引用共享原文与属性，避免反复复制。超过上下文时显式分批并记录各批覆盖；不能因为预算不足就把只处理了一部分的场景标为已完整建立网络。

初始特征与聚类、场景整体描述、实体网络构建、跨场景对应、局部补看和最终 QA 分别记账。缓存复用保留原构建成本与本次实际读取成本，不能把缓存后的低延迟当成首次端到端成本。

状态数量随实际变化增长，但原始资料、属性观测和索引仍会随视频长度增长。长视频的分块、候选检索和持久化属于后续规模实现，不能仅由短视频实验推断其性能。

## 回答与实验验证建议

起步阶段固定现有模型、原 VideoTree QA 模板、选项顺序和生成设置，把主要变化放在场景组织、记忆与导航上。最终提供相关原始材料、状态链、时序关系及其证据，不将未打开场景的导航提示当成已读取事实。

实验采用相同题目和明确的成本口径。以下分组是实现后的验证建议，尚未提交：

| 组别 | 方案 | 要检查的问题 |
| --- | --- | --- |
| R0 | 保留原 VideoTree 不变作为历史方法对照 | 与已有基线的总体差异 |
| C0 | 连续场景聚类、簇中心检索、选定材料与固定 QA | 新前端本身的表现 |
| C1 | 在与 C0 相同的读取材料上增加实体档案和时序网络 | 结构组织这一整体模块是否有效 |

C1 与 C0 的比较须冻结共同观察材料，才能区分表示与取证差异。C2 和 C3 改变了获得的材料，需要同时报告场景数、帧数、覆盖范围和处理成本。C1 是档案、状态、关系及输入说明的组合模块，不能把差异单独归因于一个字段。

旧开发集上的探索结果不能直接证明新方案泛化收益。选定实现后还需独立数据验证；本方案当前没有对应的完整准确率或耗时成绩。
