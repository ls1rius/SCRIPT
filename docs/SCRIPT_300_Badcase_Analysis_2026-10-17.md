# SCRIPT 修复后 300 题错误案例分析

2026 年 10 月 17 日，新加坡时间。分析对象是本轮共享新建 M0 的常规读取和剧本引导读取，共 600 条运行记录；逐题统计之外，深入检查了 14 个案例的选项、观察、核验、最终输入与输出，并查看了 5 个案例保存的实际输入帧。

**本轮最明确的失败发生在证据到选项的语义转换。新增逐项比较经常同时认可互相冲突的选项；少看策略又会预设结论、选择错误时间段，并在取证没有解决缺口时直接结束。视觉核验本身也会将复合命题的部分支持扩展为整条支持。** 这三处问题会相互放大，继续增加普通观察轮数或只修 JSON 解析都不足以解决。

结果以实际完成的 [run_summary.json](../workdirs/script-repairs-300-20261016-r1/run_summary.json) 为准。旧的 10 月 16 日状态文档仍停留在提交时刻。全部诊断保存于 [analysis_badcases_20261017](../workdirs/script-repairs-300-20261016-r1/analysis_badcases_20261017/)。

## 最终逐项比较没有形成可靠语义约束

| 现象 | 常规读取 | 剧本引导读取 |
| --- | ---: | ---: |
| 多个选项同时标为 matches | 107 | 33 |
| 五个选项的理由完全相同 | 27 | 29 |
| 错题中正确选项也被标为 matches | 44 | 16 |
| 编号一致性纠正实际触发次数 | 0 | 0 |
| 选择编号 0 的次数 | 148 | 123 |

标注答案为 0 的只有 65 题；历史 SCRIPT 选 0 为 113 次，VideoTree 为 42 次。本轮常规组选择 0 占全部题目 49.33%。这提示明显的位置偏向，但格式约束、生成顺序、取证内容各有多大作用，须用同一证据输入的选项置换回放区分。

程序 [answering.py](../script_core/answering.py) 只在恰好一项 matches 且最终编号不同的情况下纠正编号。五项全 matches、共同步骤误支持独有前提、错误引用合法事实等情况均不在该保证范围内。因此“先比较再选择”仍可表现为重复理由和自我确认。

### 清洁地板仍选重新摆家具

案例 `45fd8bca`，标注 4，两组均选 0。

常规组最终输入有 14–22 秒扫地、98–106 秒拖地、70–78 秒扫地、84–92 秒移动拖把等有效事实。最终 evidence_summary 已明确写出 sweeping、moving objects，以及 cleaning activity rather than rearranging；option_alignment 却把重新摆家具和清洁地板同时设为 matches，最终选择重新摆家具。五项理由重复同一句动作描述，缺少“搬家具服务于什么目的”的比较。

引导组计划的理由直接写成“移动椅子说明重新摆放”“再次移动强化该目标”。它检查了 77–85 与 84–92 秒，观察产出搬动家具的复合描述，核验均未形成有效事实，最后仍选择重新摆放。这里同时存在规划预设和无有效取证后的结论补全。

[完整案例与原始调用](../workdirs/script-repairs-300-20261016-r1/analysis_badcases_20261017/case_45fd8bca.json)。

### 绣布画图案被后期刺绣事实覆盖

案例 `8345d177`，标注 4，历史选 1，本轮两组均选 0。

常规组 claim000010 明确记录 42–49.5 秒用笔在绣框布料上画图案；这条事实确实保留在最终回答输入中。模型却把缝合、剪裁、购买、电脑设计、用笔画图五种互相冲突的前期准备全部标为 matches，全部引用 133–141 秒共同的刺绣与转动布料事实。

引导计划正确指出“要区分准备阶段”，但只检查 14–22 秒，得到泛化的“布放在绣框上，准备刺绣”。最终五项理由完全相同，选择 0。引导最终粗描述中仍保留了画图线索，因此本例不能简单归因于 12 窗口限制删掉了全部关键描述。

这个案例直接否定“只要把选项差异送入观察，最终比较自然就会使用它”的假设。关键事实已存在，但共有后续步骤仍在替独有准备步骤背书。

## 剧本引导规划提前决定答案且没有根据取证结果调整

实际 286 题启用了引导流程，另 14 题未启用。286 题中，计划为 0/1/2/3 个检查的题数分别是 6/98/67/115；其中 184 题的所有实际检查都在前 60 秒内。前期准备题可能适合早期读取，但涉及整体变化、后续结果和跨阶段工具的问题需要不同时间定位。

[controller.py](../script_core/controller.py) 在计划检查执行完后，以 script_read_plan_complete 结束；计划执行过程中不会根据核验失败或剩余选项区别重新生成计划。检查完成并不代表检查目标得到答案。引导组 295 条正常回答中有 112 条最终没有有效视觉事实，其中 106 条实际进行了至少一次视觉读取；常规组相应数字为 19 条。

### 烤面包退步成制作披萨

案例 `f1d2978d`，标注 4，常规组本轮修对为面包，引导组退步成 0 披萨。

引导计划把三个 goal 直接写为“制作披萨”“制作糕点”“收集饼干原料”，分别对应候选结论；这不是中性的观察问题。最终只保留“男子在平面上处理面团”的一条事实，五种烘焙目的全部 matches，选择披萨。

正确的取证目标应能区分成品与加工过程，例如形状、是否加馅或铺料、面团如何进出烤盘；不能把待判断的烘焙类别当成窗口的既定活动。常规组本例没有有效视觉事实，依据更完整粗描述答对，也说明两组的最终文本输入差异需要单独控制。

## 视觉核验会接受部分支持和不可靠复合事实

### 种苗左右手及顺序仍然错误

案例 `e48b8359`，标注 4，两组仍选 0。

常规组已经观察具体左右手，但记录中出现不同序列，并都获得 supported。两条“右手拿、交给左手、左手种”的复合记录，其 verifier 的 distinguishing_facts 只支持“右手拿、交给左手”，没有证明种植用手；整条命题仍通过了核验。

引导组把观察拆成三条后，verifier 又对三条 action 同时输出 supported 和 process_visible=false；程序按动作过程要求拒绝将它们作为有效事实。最终答案输入因而没有有效视觉事实，却仍确定选择另一套左右手顺序。

本例需要逐事件的过程帧和身体参照，不能用“引用了三帧”替代具体动作确实可见，也不能把 verifier 的 supported 当成人工真值。查看的抽样帧不足以独立确认所有交接顺序。

[完整案例](../workdirs/script-repairs-300-20261016-r1/analysis_badcases_20261017/case_e48b8359.json)。

### 面团正确复合顺序整条丢失

案例 `0c17076e`，标注 4，常规组正确，引导组选 0。

引导组两次 observe 都说“桌面滚动，然后面粉，最后托盘”，但把整个序列写成一条复合 action；verify 返回 unresolved 和 process_visible=false。最终无有效事实，比较表却把“面粉先于桌面”和“桌面先于面粉”两种相反顺序同时设为 matches。

需要把一个重复加工周期中的独立动作与时间关系保留下来；跨周期混合事实也可能制造顺序。这里不能仅靠最终引用合法性排除错误。

## 转折语义和标注可辨性需要单独处理

抽屉题 `d30c1b6c` 的常规组已有抽屉相关 supported 记录，却引用写字事实支持“查看纸张”并选 3；引导组只看写字并选 2。实际帧显示抽屉操作与离开桌面，但所查窗口开始时抽屉已经打开，说明记录中的“打开”方向仍需追查。它既包含最终选择不理解活动转折，也包含复合视觉描述需要复核的问题。

蛋糕题 `22d22f02` 的引导组引用“在厨房”“面朝门”证明“移动到完全不同房间”，没有位移过程，也没有比较前后半段。维修转折题 `3a94a8d4` 则从常规组的拆卸轮轴退步成引导组的“补洞完成”。这类题需要前一活动、转变事件、后一活动的关系，单一局部动作或结果完成不能自动充当转折。

切菜题 `811deb7d` 的 cuts 与 chops 语义重叠。常规组四条事实都写 cuts，却选 chops 并把 cuts 标 unknown；引导组同样的核心事实又选 cuts。这证明比较不稳定，同时也提醒该题不能当作视觉动作分类的干净监督信号。

## 视觉读取仍有价值但当前多轮消耗较高

磨姜题 `0c51c89d` 中，VideoTree 选切丁，两组 SCRIPT 都通过 grater 和 grating 事实选对；引导组三次读取得到 5 条有效事实，保留了视觉纠错能力。这类工具清晰的正例值得保留。另一些常规组答对的题，如厨房目的、楼梯安装，支持记录仍然宽泛或五项全部 matches，不能只因标签答对就视为可靠推理。

本轮常规组平均 observe 为 48.52 秒、verify_claims 为 32.05 秒、assess 为 13.02 秒、gate 为 18.71 秒、answer 为 11.28 秒。历史 answer 平均仅约 2.18 秒、gate 约 7.49 秒。新增比较增加了文本生成工作，但当前没有看到净准确率收益。两次运行的源码、M0 和共享资源条件同时变化，这些成本差异属于实测描述，不能全部归因于一段提示词。

## 后续验证顺序

优先隔离最终选择问题。复用本轮每题冻结的最终输入，在固定 300 题上对照简短直接选择与当前五项比较；再固定每道题的证据进行选项置换并映射回原编号，检查语义答案是否随位置变化。这样可以衡量输出格式和位置偏向，避免把重新取证与新建 M0 的变化混入。回放结果须同时报告修对、改错、格式失败和耗时。

第二步隔离少看策略的因素。先保持相同最终粗描述输入，再比较读取数量与调度方式；把仅少看、仅筛描述和二者一起改变分开。在 300 题比较中检查核验未解决缺口时的后续行为，不能把完成静态计划当成完成语义检查。对转折和顺序题，应按选项需要的事件关系定位前后阶段，而非依据问题是否含“概括”来统一处理。

第三步验证事实核验。以种苗、面团和抽屉等案例检查独立动作、身体参照、动作方向、过程可见性及反例；明确一条复合命题每个部分分别获得什么支持。不能通过放宽 action 的过程要求来消除零事实现象。

运行可靠性中的答案 JSON 截断、软截止和前置条件解析继续修复，但其本轮直接上限仅为每组 5 题。新 M0 已完成 300/300 且全部摘要可读，下一轮应把精力集中在上述语义环节。所有改动仍应在同一固定 300 题上报告双向变化；该题组属于开发评测。
