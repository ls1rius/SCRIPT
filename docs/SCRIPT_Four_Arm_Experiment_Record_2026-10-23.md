## 1. 实验与方案定义

| 方案 | 标识 | 查询行为 |
| --- | --- | --- |
| ① | `cluster_qa` | 以视觉特征定位单个连续场景，读取原始字幕后使用原 QA 回答 |
| ② | `temporal_local` | 与①使用同一入口场景，增加由原始字幕抽取的局部时序实体记忆，再回答 |
| ③ | `summary_deep` | 按需深入读取多个场景的字幕，场景内实体独立，必要时少量补看，最终回答 |
| ④ | `temporal_cross` | 消费③在回答前导出的同一份证据，增加跨场景实体对应和历史，再独立回答 |

③④的场景、字幕、读取秒数及补看观察必须一致；④不读取③的答案、理由、置信度或评分标签。文本身份对应不升级为视觉核验，也不自动证明观测空档内的状态持续或变化原因。

正式四组实验与日常查询不同：正式实验分别生成③④的对照答案；日常查询仅生成所选方案的一次最终答案。

## 2. 数据、模型与预算

| 项目 | 设置 |
| --- | --- |
| 数据 | EgoSchema 公开答案子集中的固定 300 题，四组使用同一清单与原始五个选项 |
| 清单构造 | 种子 0：先按排除两个调试 ID 的规则抽取 100 题，再从剩余题目打乱后追加 200 题 |
| 清单溯源 | 本机缺少更早的历史 cohort 文件，未声称与缺失历史清单逐项一致；本轮清单和输入哈希已保存 |
| 描述 | 已提供的原始逐秒 LaViLa 描述，保留原文、时间和来源 |
| 视觉特征 | EVA-CLIP-8B，用于连续分段及中心检索 |
| 抽取与 QA 模型 | 本地 Qwen2.5-VL-7B-Instruct，bfloat16；不声称复现论文 GPT-4 成绩 |
| 生成 | `do_sample: false`；QA 默认 `max_new_tokens: 1024`，实体抽取路径上限 4096 |
| 目录预算 | 600 processing_seconds |
| 在线预算 | 1500 processing_seconds，最终回答预留 45 秒 |
| 单次在线调用上限 | 150 秒；构建调用上限 600 秒 |
| 深搜 | 最多访问 4 个场景；每个抽取请求读取整个场景的原始字幕，每页最多 3 个实体 |
| 补看 | 启用有界稀疏视觉补充；④复用③已取得的观察，不额外读取图像 |

模型精确文件集合哈希和软件版本见 JSON 快照。当前验证环境主要版本为 Torch 2.7.1+cu126、Transformers 4.57.6、lm-format-enforcer 0.11.3。

## 6. 默认入口切换：方案 3 为默认，方案 4 可选

### 6.1 代码行为

- CLI：`script_qa.py query` 默认读取方案③配置；添加 `--scheme4` 显式启用④。
- 配置：`configs/script.yaml`、`configs/script_local.yaml` 及低层默认值使用 `query.pipeline: scheme3`，仍支持 `scheme4` 与 `legacy`。
- 方案③：`summary_search/` 完成证据准备及一次最终 QA，不执行跨阶段实体关联。
- 方案④：summary 搜索仅导出回答前证据，`cross_stage/` 复用证据进行关联及一次最终 QA，不生成③的对照答案。
- 续跑：使用各自的 `scheme3_request.json` / `scheme4_request.json`，禁止在同一目录混用方案或重置中断预算。
- 本机 smoke 与 VS Code F5 默认③，本机普通查询分别输出到 `scheme3/` 与 `scheme4/`。
- 输出的 `scheme`、`pipeline`、运行配置与费用汇总均标记实际选择。

本次修改的是日常入口及配置，不改变正在执行的四组冻结评测。补跑目录的源码和控制哈希已核对无变化，原进程继续运行。
