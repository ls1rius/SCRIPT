# 在原 SCRIPT 回答协议下检验记忆压缩

2026-11-01 更新：B/C 独立评测产物已按用户要求清理，仅保留[历史结果与成本记录](history/BC_Experiment_Record_2026-11-01.md)。A 原始输入和回答保留，E/F 所需公共来源观测保留；下文涉及 B/C 的运行步骤为历史协议，不代表仍有可恢复的原始产物。

## 本轮只回答什么

在原 SCRIPT 实际读取的相同证据上，只替换最终 Description 区域的证据表示，检验语义记忆能否保持回答质量、减少输入和总处理成本。上游检索、场景选择、实体时序组织和补看均复用冻结结果；这是最终回答干预实验，不是重新运行完整上游流程。

原 SCRIPT 的最终输入已同时包含完整已读描述、旧时序记忆和已接受视觉观察。因此，覆盖修复首先是“不允许漏掉任何已读来源”的约束，而不是增加比原 SCRIPT 更多的证据。旧稀疏及后续规范化实验已按用户要求删除；不恢复它们、不引用其成绩作为有效主对照，也不声称本轮测出了相对那个有缺陷实现的修复增益。

C 的共享抽取实现和合格产物保存在本实验的独立快照内，抽取成本仍需记账。

## 三个主组，每次只改变一个清晰的因素

| 组 | Description 中的证据 | Description 外的原提示、旧时序记忆及视觉观察 | 作用 |
|---|---|---|---|
| A：原 SCRIPT 重放 | 原调用原样，不重新生成模板 | 原样保留 | 严格的历史复现与新鲜主对照 |
| B：完整原文重新排版 | 全部已读描述装进可逆的逐条证据容器；保留每次采样，不合并相同文字 | 与 A 逐字相同 | B−A 检查表示容器/排版本身的影响 |
| C：同容器的语义表示 | 与 B 相同的来源行、顺序、ID、采样时间；正文替换为具名语义事实及必要原文 | 与 A、B 逐字相同 | C−B 检查语义化表示的影响；C−A 给出相对原 SCRIPT 的实际净效果 |

主比较预先指定为 C 对 A；B 为解释机制的桥接对照。C 对 B 包含语义抽取、角色表达和原文替换的整体影响，不进一步声称已隔离每个分类或角色规则的单独贡献。

不在本轮同时切换 JSON 回答、不删除旧时序记忆、不调整系统提示、不重排选项、不加新看图。保留旧时序记忆是有意固定变量；本轮 C 的名称为“语义表示替换”，不能称为完全移除原有时序上下文的方案。

B 使用 `observations` 容器，每条包含 `caption_id`、`frame_index`、`sample_interval`、`evidence.original_text`。C 使用同样的外层行及 metadata，只替换 `evidence` 字段为动作/属性/状态/关系/变化/结果/事件联系及分类原文。相同原文在不同采样时刻必须展开为各自的行。已接受视觉证据在原有位置固定保留；C 不再将其转写一遍，避免只给某组重复的视觉信息。

## 固定哪些条件

- 固定原来同一批 300 题及顺序，全部按固定分母评分。首 20 题只用于预先规定的技术验证，是这 300 题的前缀，后续复用，不额外增加样本数。
- A 的输入从原始 `videotree_qa` 调用参数读取，逐题与已保存的原输入对等，而非根据当前模板重新拼装。
- B/C 只允许修改唯一的 Description 区域。系统提示、用户提示的前后缀、问题、选项及顺序、答案格式指令、旧时序记忆、已接受视觉观察均做相等断言。
- 使用原 SCRIPT 的冻结后端、生成与解析代码、检查点和软件版本。固定精度、seed、`do_sample=False`、`max_new_tokens=1024`、上下文上限及相同的最终 QA 预算。原配置新增的权重 revisions 仅可作为核验信息，不作为允许换权重的理由。
- 三组通过原 `videotree_qa` 路径生成一次最终答案，保持原单字母回答与原解析；使用原回答路径。语义抽取和最终回答分开计费，不能因 C 额外抽取而单独减少其最终 QA 额度。
- 六种顺序 ABC、ACB、BAC、BCA、CAB、CBA 按题目索引循环，平衡共享 GPU 时间变化；不按已知对错改变顺序。

## 技术验证和执行顺序

1. **CPU 输入审计。** 对全部 300 题验证 A 与原调用参数完全相等；B 的序列化可以无损还原原文、来源 ID、采样时间和所有重复观测；所有组的固定区域必须一致。当前准备工具只完成 A/B 输入和这一步审计，不发起 GPU 任务。
2. **冻结 C 的渲染器与质量合同。** C 在同一 Description 位置输出证据，不能留下空 Description 再把事实追加到回答指令后。每个已读 caption 必须对应最终可见事实或完整原文；没有实体或抽取失败不能使该行消失。不接受用词集合覆盖率证明语义完整。不能静默裁剪，也不能回退到 A 后仍计作 C。
3. **来源盲审。** 按来源哈希固定抽取 100 个真实证据单元，审查输入不含问题、选项或标签；检查类别、角色、否定、修饰、时间及原文保留是否忠实。另对绘画表面/工具、移动起终点、属性/临时状态、变化/结果/事件联系运行固定功能样例，缺类不能靠强行生成补足。记录问题与失败，质量合同未满足时 C 保持未就绪；不以 benchmark 准确率决定修复。
4. **先重放固定前 20 题的 A。** 核对权重/软件/输入、预算与原预测。若不一致，先定位复现差异，不通过调提示、换解析或按正确率筛选来追到 62%。保存原响应和差异；不能仅凭 20 题一致宣称全部 300 题复现。
5. **技术合同满足后，运行前 20 题的 B/C，再执行剩余 280 题的三组。** 功能门槛与启动条件不看准确率。前缀答案只生成一次；若实现发生变化，应新建版本，保留旧尝试和成本，不拼接旧版前缀。
6. **完整审计 A 的 300 题复现。** 报告与历史预测不一致的数量、逐题原响应及新鲜 A 成绩。若 A 未复现历史 186/300，C−A 仍只作为当前冻结协议下的配对结果，不能声称严格复现了历史原方案。

C 可引用已验证的共享抽取记忆，但必须核验相同源文本、全部来源 ID/时间、模型/精度、抽取代码与提示哈希、配置、预算及完整调用账本；复制为本轮不可变快照，并分列继承与新增花费。最终回答须在本实验独立生成。缺少或不合格的记忆使用预先冻结的抽取器生成；若抽取实现修订则新建产物版本。来源覆盖完整与分类检查完整分别统计：已检查、失败、预算耗尽未检查、拒绝角色以及残留原文均公开。检查过而没生成某类事实，不等于该类信息不存在。

## 评分、错误及成本

主分数保持原解析，便于对应历史 SCRIPT。对同一原始响应另做严格单字母/唯一完整选项文本审计，记录原解析是否误把人物 C 当选项；审计不新增模型调用，不按正确标签帮助解析，不悄悄改主分数。

所有格式、schema、上下文溢出错误保留并计错，不因错误重答或删除题目；上下文溢出不会静默删描述、裁记忆或改用原始输入。预算/执行失败与普通答错分列。基础设施 OOM 可独立恢复，但失败调用、预算和所有尝试成本保留；成功答案不重跑。可恢复的格式错误只结束本题本组，随后继续其他组和题目。

报告至少包含：

- 固定 300 题准确率、错误数、待执行数；阶段结果只按三组共同完成的题目比较，不把待执行当错题。
- A 对历史预测的复现差异；C−A、B−A、C−B 的纠正/退化数量、净百分点及配对统计。C−A 是主比较，其余为解释性结果，不从多个比较中挑最大的改善宣称主结论。
- 最终实际输入 token 的均值/中位数/P95、最终 QA 时间；完整原文回退/重答必须为零，溢出及失败单列。
- 语义抽取、CPU 准备、最终 QA、模型冷启动和恢复失败的成本分别列出；继承的抽取也不是免费。端到端成本另列原上游分摊成本，不能仅凭最终 QA 较快宣称整体加速。
- 逐来源覆盖、逐类检查状态、原文残留比例和角色审计；按空旧记忆/非空旧记忆、来源提取不完整标记分组，仅作预先指定的诊断。

这是已反复使用的开发集，结果不宣称独立测试集泛化。若 C 相对 A 只有少量净增，应报告不确定性；保持准确率、压缩输入和总成本是分别评价的指标，不能用共享 GPU 的非受控耗时掩盖准确率下降。

当前执行状态以运行目录中的队列、进度和报告为准。

新实验曾自动在 GPU 1 启动，前 20 题 A 的预测全部复现原记录，前三组已完成相同 60 题。按用户随后指定，将新 A/B/C 实验的后续调度切到 GPU 0。
