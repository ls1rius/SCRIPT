# N：逐选项检查场景相关性

2026-11-03，新加坡时间。用户要求针对M把某个选项当成问题前提、误排相关场景的缺陷修复，并明确不需要选项换序测试。改动仅接入N，M-r13继续使用原冻结运行；默认L/E不变。

## 问题与改动

M前63题有52题空候选。52次原始调用均含全部选项，模型逐场景全excluded，程序照此终止读取。人工核实两例：打包题只围绕选项A的寻找行为筛选；熨衣题把选项A的折衣服当作问题前提。不能据此认定全部52题同因。

新增script_core/n_scene_selection.py，操作n_select_scene，当前版本N-isolated-scene-option-pairs-v5-reason-first；N总版本N-M-reasoned-pair-candidates-v7。输入仍为问题、全部选项和全部原始场景summary。每个场景/选项对一次独立调用，每次带同一问题、全部选项、明确focus_option原文和仅该场景的summary，按scene_reviews先输出本次focus_option的reason，再输出0–100 priority，最后复制anchor，程序将全部调用汇总成必填的全选项矩阵。focus_option必须与原选项ID和文本完全一致；不会将其当作已知答案。全部summary检查完后才汇总候选。原summary保持完整，额外按标点生成逐字片段summary_clauses；正分必须引用当前场景的字面片段文本，null引用只能为0分；引用了片段也可判无关给0分。先解释场景实际动作与待查动作的联系，给分后再选择引用；0表示无关，正值表示值得查看，不是选项正确概率。片段引用只能约束来源，不保证模型解释正确。

程序不再接受另一个可覆盖逐选项判断的全局排除结论：某场景至少有一个正分即进入候选，排序分取该场景各选项分数最大值，同分按目录顺序。全零场景排除，全部全零仍允许空候选，不强制数量、时间覆盖或自动全选。反对某选项的可区分活动也可能相关，summary未写全选项的目的或细节不等于无关；summary仍只用于导航，不作为最终回答证据。

N后续仍只在该封闭候选队列中按序查看，足够即停、候选耗尽即停，资源上限单列。来源角色抽取和原文保留沿用现有N v2，本次未用新的导航测试替它们宣称准确率改善。

## 记录与资源
