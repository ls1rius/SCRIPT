# 每秒描述优先的少看流程

2026 年 10 月 17 日，新加坡时间。针对[上一轮分析](SCRIPT_Guided_Performance_Analysis_2026-10-17.md)中“原始每秒描述完整传入，却未被有效综合”的问题，本次将少看流程改为先作描述判断，再按具体缺口补看。代码和 CPU 验证已完成，真实模型效果待复验。

## 行为变化

原流程先根据窗口描述生成读取计划，再补看，最后回答；缺少独立保存的描述初判，而且观察目标被统一替换成泛化描述。新流程为：

1. 在适用少看的题上，直接读取原始 LaViLa 每秒描述及原时间，去掉窗口包装造成的重复。不同秒出现相同描述仍分别保留，不合并为一次动作。没有外部描述时使用已有窗口描述；超出查询合法范围的生成描述不冒充范围内信息。
2. 一次 `caption_review` 调用先回答，再列出最多一个会影响选项选择的可见缺口。初判保存具体描述引用；这是描述依据，不创建已核验视觉事实。
3. 描述足够时返回空检查，零读图直接复用初判，避免对同样输入再猜一次。需要补看时，给出具体中立问题、窗口及附近描述引用；观察和验收收到原检查问题，不再统一抹去具体区别。
4. 每次检查后使用完整描述、已核验局部事实及带时间的未知信息重新判断；下一次仍最多一个窗口，总计最多三次，已查及高度重叠窗口仍排除。
5. 补看后最终回答接收完整去重时间线和有效事实，移除重复的窗口描述与场景摘要，不输入先前选择作为答案提示。保存初判、历次描述判断、最终选择及是否改变，方便离线计算修对和改错。

描述时间线采用平铺文本；候选仍保持编号与全文对应，模型输入不再额外重复整组选项差异文本。描述初判与首次检查共用一次模型调用，替代原来的首次读取规划；每轮判断也替代原规划，不额外叠加同类调用。普通题的问题解析暂时保留，不能将本次变化说成已经解决全部解析开销。

## 配置和证据边界

当前默认 CLI 的 `configs/script.yaml` 使用修复后的常规读取：`reading_policy: coverage_first`、`caption_first: false`；`configs/script_coverage.yaml` 提供显式同策略配置。要启用本报告的描述优先少看流程，使用 `configs/script_guided.yaml`（`script_guided`、`caption_first: true`）。在少看配置下，`query.caption_first: false` 保留旧的逐次 `read_plan` 流程作为消融。严格计数、否定、最后一次等不适用少看的题沿用覆盖流程。已提交的两组复验继续使用冻结配置，不随工作区默认值改变。

描述初判、规划停止、零读图均不会把证据状态提升为充分；描述 ID 不能进入视觉事实引用字段。检查问题是待查线索，不能被当作已发生的动作。既有视觉核验的动作/状态语义漏洞尚不属于本次修复，仍需通过独立修复与验证处理。

新增实现位于 [caption_first.py](../script_core/caption_first.py)，控制流程位于 [controller.py](../script_core/controller.py)，约束和提示分别位于 [schemas.py](../script_core/schemas.py)、[prompts.py](../script_core/prompts.py)。

## 已完成验证

**212 项 CPU 检查通过**，日志保存到新实验的 `cpu_tests.log`。新增 8 项检查覆盖：描述直接回答无需读图/再次回答、具体问题传给观察、事实反馈及窗口排除、三次上限、规划失败后保留描述作答、原始秒级时间与文本保留、描述/视觉引用隔离、真实约束解码器及配对评分中的错误计入。部分性质由同一项检查同时覆盖。

对固定 300 个 M0 的原始描述做了逐条审计：**54,000/54,000 条原文和时间均被新时间线保留**，没有重新建库，没有使用答案。审计记录为 `caption_timeline_audit.json`。

CPU 检查验证流程边界和记账，不证明模型准确率提升。初判来自同时回答和安排检查的 `caption_review` 调用；它不是独立的 VideoTree 提示模板控制组。初判与终判的配对收益可观察，但仍混合了补看事实、后续判断与最终回答提示的影响，不能当作随机消融得到的纯视觉因果收益。

## 真实模型复验

少看运行目录：[script-caption-first-300-20261017-r1](../workdirs/script-caption-first-300-20261017-r1/)。两组统一比较目录：[script-caption-first-matched-300-20261017-r1](../workdirs/script-caption-first-matched-300-20261017-r1/)。源码、输入、共享 M0 指针和历史对照均保存哈希；原实验与 M0 不修改。

先运行 8 道定向开发诊断，包括清洁、刺绣、工具、抽屉、烘焙、陶艺、踏板车，以及一题严格范围控制。检查合法答案、描述初判记录、规划失败、读取上限和预算。诊断仅作工程验收，不作为准确率估计。

工程诊断通过后，两个依赖作业自动运行原固定 300 题的少看流程，每卡两个独立分组。另两个常规读取作业分别接在对应少看作业结束后执行，同样各处理两个分组，合计另 300 题；使用 afterany 依赖，少看作业保留逐题失败时仍可继续常规对照。最多同时两张 H200；8 题诊断期间只用一张。

两组推理源码逐文件哈希完全相同，题目分组和 M0 路径完全相同，配置只改 `query.reading_policy`。覆盖组仍执行覆盖流程，描述优先及零到三次细看分支仅在符合条件的少看题上生效。本轮没有改为纯文本建库，也没有重新构建 M0。旧成绩和 VideoTree 仅作历史对照，不替代本轮任一组的新推理结果。
