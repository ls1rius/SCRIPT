## 1. 问题与初步判断

当前主要瓶颈是字幕实体抽取：对多个场景反复调用自回归大模型，生成包含实体、属性、状态、原因及来源的较长结构化输出。

优化优先级：

1. 先消融区分“读取更多场景”与“实体记忆”的准确率贡献。
2. 优先测试保留语义与来源的输出压缩：字幕引用回填、短字段编码。
3. 测试轻量候选抽取器与复杂语义处理的组合。
4. 独立研究按证据缺口选择抽取深度；这一项可能改变现有抽取范围，不能视为等价实现。
5. 分析解码阶段耗时，再测试结构化生成引擎、前缀缓存与批处理。

以上排序是结合论文与本地日志形成的工程判断，不是论文已在本项目上验证的结论。

当前 `caption_temporal_observe` 按场景读取该场景全部带时间戳字幕，不逐帧调用视觉模型。

## 4. 优化方案

### 4.1 优先做诊断消融：实体记忆的独立收益

固定已有 `summary_deep` 的场景集合、字幕、顺序和视觉补充证据，比较：

1. 原始证据直接 QA，不附实体记忆。
2. 原始证据加当前实体记忆。
3. 原始证据加精简后的实体记忆。

保持 QA 模型、选项顺序、生成设置和输入上限一致。对附加记忆使用同样的完整实体选择策略，并报告超限时的省略记录。

这个实验可复用已有取证产物，先判断实体记忆对最终回答的作用。它不验证在线导航是否仍然有效：场景集合由旧流程选出，不能据此声称去掉实体抽取还能保持原来的端到端准确率。后续需要独立测试字幕驱动或轻量记忆驱动的导航。

### 4.2 第一项工程改动：引用式输出与短字段编码

目标：减少已有信息的重复生成，同时保持最终存储的标准网络、来源与不确定性语义。

#### 字幕引用回填

模型主要输出实体、来源字幕 ID、连续性/变化判断，以及确需选择的属性或动作文本位置。由程序按引用回填已经保存的原始状态描述、原始时间与来源。

示例仅说明传输格式，尚不是最终 schema：

```json
{
  "entity": "metal rod",
  "observations": [
    {"caption_id": "C176", "continuity": "initial"}
  ]
}
```

约束：

- 只有能由输入唯一恢复的字段才可回填；属性、动作、角色等需要选择时，仍应输出合法引用或文本位置。
- 必须显式保留实体归属及初始、相同、变化、未知等语义判断。
- 缺少原因依据时保持 unknown，不由程序猜测因果。
- 验证引用属于当前原始材料，实体标签及字段值受到自身来源支持。
- 编码后的输出应能恢复为标准存储格式；保留原始模型输出与恢复记录。

现有重试逻辑已经约束状态原文与自身字幕引用绑定。新方案须保留这种绑定，避免生成完整原文后再发现引用错位。

#### 短字段编码

当前 `backend.py` 中，`compact_temporal` 条件仅覆盖 `temporal_observe`；字幕路径使用 `caption_temporal_observe`，未进入该分支。当前实验的 `temporal_compact_keys` 配置也为 false，因此单纯开启配置并不足以覆盖字幕实体抽取。

拟扩展 `temporal_codec.py` 对字幕引用字段的支持，同步适配 schema、提示、解码、修复路径和来源别名。只压缩传输键名，落盘仍保持标准字段；不得改变事实、引用或模型/QA 输入限制。

短字段和引用回填分别测试，再组合测试。格式变短不代表模型的选择必然不变，需要推理回归验证。

### 4.3 轻量候选抽取与复杂语义处理分工

候选流程：

```text
原始场景字幕
    → 轻量模型识别实体片段及部分显式属性
    → 绑定原始字幕与文本位置
    → 对状态变化、指代、歧义及复杂关系调用大模型
    → 校验并写入标准时序网络
```

优先比较 GLiNER/GLiNER2；需要关系分类时另测 GLiREL 类方法。保留候选遗漏的恢复入口，避免候选过滤后大模型再也看不到关键对象。

评估不能只看实体名称：需要检查普通物体召回、同名不同实例、状态改变、动作角色、关系方向和来源引用。轻量模型支持的普通实体/关系抽取，不等于已解决视频物理身份与状态持续时间。

### 4.4 按证据缺口选择详细抽取深度

**2026-10-23 讨论更新：保留当前问题无关抽取路线，并保留问题驱动抽取的过渡版与按问题选帧的新版④。** 用户明确要求过渡版也独立保留，不能被新版④替代。当前为原版③、原版④、过渡版、新版④四组对照；最新实现与排队记录见 §4.4.6，历史见 §4.4.4–4.4.5。尚无新方案的真实 GPU 结果，默认入口未切换。

抽取路线的区别：

| 路线 | 场景选择 | 场景内实体与关系构建 | 当前状态 |
| --- | --- | --- | --- |
| 当前路线：问题无关抽取 | 由问题引导，按需访问场景 | 对已访问场景，尽量保留原始字幕支持的实体、属性、状态变化、关系及来源；不向抽取器提供问题或选项 | 保留现有实现与默认行为 |
| 过渡版：问题驱动的选择性抽取 | 按问题选簇，规划器仍先读整个已访问簇的原始 summary | 只抽取当前需要的实体信息，保留来源链接及后续增量补充；保留最初 r1 实现的独立观测表达 | 在 r4 中作为独立实验组保留 |
| 新版④：问题与缺口驱动选簇/选帧 | 问题与当前缺口共同引导选簇，并在簇内选择相关代表帧 | 仅先读代表帧对应 summary，按需抽取实体、属性、状态、原因及关系；沿来源或扩展相关帧继续补充，并保留④的跨场景关联与历史 | 与过渡版同时排队，独立记忆和结果 |

备选路线不要求先为每个实体建立全面信息，也不要求先完成整个视频的实体关系网络。预期目的是减少与当前问题无关的结构化生成，但实际耗时与准确率收益仍需实验验证。它与方案③/④是否执行跨场景身份关联是不同维度，不另行编号为四组实验中的新方案。

候选流程是先读取场景目录，以问题选择场景和场景内的代表帧，仅读取这些帧对应的原始 summary，再决定需要哪些状态变化或交互对象。此路线借鉴 VideoTree、DrVideo 和迭代式 VideoAgent。

保留整个视频的粗粒度概览、原始字幕及必要的相邻事件上下文；不只按问题中出现的名词过滤对象。对全局、跨阶段及穷尽类问题继续检查时间覆盖，未覆盖或预算不足须明确记录。

这一项可能改变现有“问题无关抽取、保留已访问场景中可获取实体属性”的设计约束，应作为独立研究分支，明确记录改变的抽取范围与遗漏风险，不能悄然替换主线或标为无损压缩。

#### 4.4.1 参考本地 VideoTree 的按需展开

已核对 `../VideoTree/adaptive_breath_expansion.py` 的 `launch`：先聚类、选择代表节点，根据问题相关性评分决定是否增加簇数；`../VideoTree/depth_expansion.py` 的 `hierarchical_clustering_with_external_primary` 根据相关性分数选择不同细分深度。这提供的是问题引导的粗到细取证思路；实体记忆跨查询增量补全是本项目新增设计，不是该代码已经实现的能力。

本方案同时控制三个维度：选择哪些场景、在场景内先读哪些代表帧对应的 summary，以及从选定文本中抽取哪些实体信息。簇外和簇内都始终围绕原问题与当前证据缺口进行选择；不使用“离簇中心最近”代替“与问题最相关”。进入场景不再强制读取整簇原始文本、枚举所有实体或生成实体的全部属性。

```text
当前问题 + 已有部分实体记忆 + 场景目录
    → 判断缺少哪些实体、属性、状态、关系或时间信息
    → 问题与缺口引导选簇 → 在簇内按问题与缺口排序代表帧
    → 只读选中帧对应的原始 summary，利用实体来源链接优先回读
    → 只抽取当前缺口及必要交互对象，输出增量
    → 按④的标准校验来源、组装状态/变化原因，按需关联跨场景实体与历史
    → 证据足够则回答；否则继续扩展同簇相关帧/相邻时刻，或重新按问题选择其他簇
    → 保存部分记忆与索引，供后续问题继续补充
```

例如，首次问“用什么工具切菜”，只需建立切菜事件、工具、操作对象及其来源，不必同时抽取工具的颜色、材质。后续问“工具是什么颜色”时，从该工具已有的来源链接回读原文，必要时检索其他出现片段，再补充颜色。若文本未提供颜色，则保持未知；只有确有视觉缺口且预算允许时才补看图像。

#### 4.4.2 实体与来源 summary 双向索引

当前来源是原始带时间戳的逐秒 summary，代码称为 `caption`。应区分它与场景目录的生成式摘要 `scene.description`：目录摘要用于导航，事实抽取与补充回读使用原始 summary。当前 `caption_temporal.commit_page` 已保存 `source_captions`，属性、状态、关系和变化原因已有 `source_caption_ids`；新增设计在此基础上提供直接检索和增量管理，不重复存储整段原文。

拟提供以下索引与记录（字段名为设计示意）：

| 记录 | 用途 |
| --- | --- |
| `caption_id → 原文、视频、场景、时间区间、来源版本` | 按 ID 直接定位原始文本；原文只保存一份 |
| `entity_id → source_caption_ids` | 汇总实体各条已验证事实的来源，快速回读相关 summary |
| `caption_id → entity_ids / state_ids / relation_ids` | 反向定位该 summary 已产生的结构化记录，便于复用和去重 |
| 每条属性、状态、关系、变化原因 → 自身来源 ID | 保留事实级证据，实体级来源汇总不能代替具体事实的来源 |
| 实体/场景的抽取记录 → 已查字段或关系、时间范围、来源 ID、抽取版本、待补缺口 | 判断哪些工作已经完成，哪些仍需补充；记录不代表全场景已完整抽取 |

一条 summary 可支持多个实体，一个实体也可链接多条 summary。后续新发现的相关 summary 可以加入来源集合，但“候选相关文本”须与“已支持事实的来源”区分，只有校验后才成为事实证据。实体已有来源只是优先回读入口，不限制后续只能读取这些片段。

#### 4.4.3 增量补充和复用约束

- 支持同一问题多轮补充，也支持同一视频的后续新问题复用已保存的部分记忆；原路径逐题初始化的 `new_network()` 不能直接视为已有跨问题持久化能力，新路径单独提供加载、保存与版本校验。
- 按“来源范围 + 所查字段/关系”记录抽取覆盖。区分未查询、已查但来源未提供、已有依据、存在冲突；未抽取不代表不存在。问到新字段时应允许重读同一 summary。
- 新请求只生成缺失字段和必要的新事实，去重后追加来源与历史；不因补充颜色等静态属性而重新枚举全场景实体或重置状态。
- 保留实体实例区分和时间语义，不仅凭同名合并；后补的较早时间观测按来源时间整合，不能直接追加成最新状态。确有跨场景身份需求时再执行对应处理。
- 原始材料与来源版本决定事实有效性，查询条件决定抽取范围。问题相关的部分抽取缓存不能标记为完整场景缓存；后续问题也不继承前一问题的答案或置信度作为证据。
- 按信息缺口扩展关联对象与相邻事件，不局限于问题中的名词；对计数、最后一次、全局或否定类问题继续检查覆盖。仅在需要时扩大到全面抽取，不把全面抽取设为每轮前置条件。

后续实现需分别验证首次查询与复用查询的耗时、模型调用/token、缺口判断和索引维护成本，并检查同源新字段补充、新来源扩展、同名实例、跨时间补写及来源版本失效。已有四组实验不作为该方案的性能结果。

#### 4.4.8 后续优化：三类连接分工与实体出现位置倒排索引

根据后续讨论，将连接按构建方式分开；以下为下一轮待实现、待验证的优化，不修改正在运行的 r4 四组冻结源码。

| 类型 | 构建方式 | 证据边界 |
| --- | --- | --- |
| 结构连接 | 提前保存场景时间顺序、帧/summary 到场景的归属，由程序维护已有边界上的连接 | 场景相邻只表示时间顺序，不表示因果或实体连续性 |
| 检索连接 | 建立轻量实体提及候选及来源位置索引；以问题和当前缺口检索相关场景、summary、帧 | 同名和相似描述可作为候选，不直接合并物理身份 |
| 语义关系 | 从已读原始描述提取显式事实；复杂身份、状态变化、交互和因果按问题缺口验证并增量保存 | 关系保留自身来源、时间及不确定性，检索命中不等于关系成立 |

同一实体出现于 k 个场景时，用实体到出现位置的列表表达归属，无需为全部场景对生成“共享实体”边。列表保留 k 条实体—场景归属；若显式展开所有无向场景对则最多有 k(k−1)/2 条边。查询时再从列表中选出与当前问题相关的场景，不必物化完整场景对集合。双向位置索引仍与出现记录数线性相关；若每个场景有多次提及，来源明细规模按实际提及次数计算。

拟采用的检索表达：

```text
候选实体/提及键 → [{scene_id, caption_ids, interval, local_entity_id, identity_status}]
已关联实体 ID   → [{scene_id, caption_ids, interval, local_entity_id, identity_evidence_refs}]
场景 ID         → [候选实体键 / 已关联实体 ID]
```

两种列表区分尚未验证的候选和已有身份依据的关联。每个出现位置保留自身身份依据，不能因一个名称相同就把整个列表视为同一实例。文本支持的身份仍标记为推断；存在竞争候选或冲突时保持未解决，允许后续修订。查询所得“共享实体场景”只用于导航；交接、使用工具、拆分、组装、状态变化及因果等仍存为独立、有时间和来源的语义记录。跨场景出现也不证明空档中的持续可见或状态不变。

当前实现已有部分基础：`temporal_entity` 实体保存 `scene_ids`，`caption_temporal._merge_caption_identity` 合并出现列表；两种增量记忆已有实体与来源 summary 的双向索引。当前没有自动展开同一实体全部场景对的代码，因此不能把潜在二次方边数当作已经发生的现有开销。尚缺的是覆盖未抽取文本的轻量提及候选索引、统一的出现记录，以及严格按当前缺口触发的身份验证。现有 `identities` / `cross_matches` 同时承担判断证据审计，不应直接作为冗余边删除。

减少索引存储与减少模型判断分别验证：使用倒排列表避免物化全部场景对；模型侧按问题筛选待核验出现位置，并按双方来源、身份判定版本及实际验证范围缓存结果。新增来源或冲突时重新评估，不能把一次局部判断缓存成对整个候选集合的永久确认。记录索引条目数、身份调用数、重复判断比例、检索召回和引用正确性，再比较总耗时；仅改变存储结构不承诺模型调用数或端到端耗时下降。

#### 4.4.9 后续优化：围绕事件实例和状态变化组织语义关系

补充采用事件实例、状态实例和变化记录组织已抽取的语义信息。当前原版④和新版④已有状态、变化、关系、来源与不确定性基础，但没有统一的多角色交接事件结构。早期 `summary_graph` 存有带角色和时间的文本事件表达，不代表本轮四组已接入同一事件层。以下为下一轮设计，r4 冻结实验保持原样。

交接事件应至少包含：

```text
event_id, event_type=transfer, action_interval / time_bounds,
roles={giver, receiver, item},
before_state_refs, after_state_refs,
source_caption_ids / source_spans, evidence_basis, identity_evidence_refs,
status, unresolved_fields
```

角色允许未知或指向待核验的局部实体；不为填齐字段猜测交出者、接收者或物品身份。一次交接可关联多个实体的前后状态。两个持有观测只能提供转移线索，未见交接过程时保存待核验转移假设及各自依据，不能直接生成已确认的“甲交给乙”事件。交接期间的短暂共同持有也不能被强制压成互斥的单一持有者。

同一人多次打开同一冰箱、同一对人物多次交接同一物品，均保留独立事件 ID。去重针对同一次事件的重复抽取，须结合来源位置、动作实例、角色与时间依据；不能只按动作名或实体对合并。不同 summary 可能描述同一事件，同一 summary 也可能描述多次动作，不能简单按 caption 数量计数；来源不足以区分次数时保持未知，必要时扩展相关帧或局部视频。

持续状态和持续关系可压缩为状态实例及关联的支持区间列表。只有实体身份、关系语义和连续性有依据时才延续同一实例；不跨越未知空档补出持续区间。首次/末次观测、实际支持区间与有效时间边界分别保存。持有者、位置或开闭等状态改变时记录新的状态实例；回到旧状态也使用新的实例，不能把“甲持有 → 乙持有 → 甲持有”压成一个甲持有区间。重复动作即使没有可判定的前后状态变化，也仍可拥有独立事件记录。

每个事件、状态、关系保留时间和原始来源，并分别标记来源类型与推断依据：summary 明确陈述的是 `caption_asserted`，不能标为像素直接观察；已有来源之间推断的关系保留推断链；未确认的角色、身份或变化保持未知。只有实际检查了帧或视频才记录对应视觉来源，视觉模型报告本身也不冒充独立核验。跨场景身份关联保留可修订依据，后续冲突时能撤销或拆分，并重新评估受影响的事件、状态和关系；索引命中不能自动继承整条推断链的确定性。

“第二次”“交接之前”“最后一次”等查询先定位事件实例及时间约束，再取前后状态和原始支持材料。检索视图须按问题保留必要的顺序与角色，不能被一般相关性截断挤掉。计数、序数和最后一次判断需检查相关时间范围的覆盖；时间边界重叠或事件缺失时不能强行排序。未检索到关系只表示现有证据不足，不作为关系不存在的依据；否定结论需要相应证据与覆盖支持。

已核对的优先修正项：`adaptive_entity.commit_delta` 当前按 `(subject, object, predicate, update)` 合并关系来源，没有区分关系在不同时间重新发生的实例，且保留首次 `caption_id`；这可能压掉重复关系的时间区别。下一版需拆分事件去重与持续关系合并，保留每次出现的时间/来源，避免静态谓词键覆盖历史。原有状态组装与关系延续逻辑也要检查显式终止、恢复、未知空档及跨场景身份修订。原始 summary 和逐次调用仍保留，可用于回溯核对；不改写冻结结果来冒充修正后的实验。

验证至少包括：同人同物多次动作、同一物品多次交接、同名不同实例、回到旧状态、未知观察空档、仅凭前后持有推断交接、缺失关键片段、来源乱序补充，以及撤销身份关联后的事件/状态重建。分别检查事件数与角色、时间边界、来源、状态压缩和序数查询；性能上记录新增事件抽取/验证成本与减少的重复记录，不能预先承诺提速。

#### 4.4.10 独立优化版④：`optimized_scheme4`（2026-10-23）

用户确认将上述优化落实到新方案，并明确以当前新版④为基础。新增独立实现 [`optimized_entity.py`](../../script_core/optimized_entity.py)、[`optimized_memory.py`](../../script_core/optimized_memory.py)、[`optimized_sampling.py`](../../script_core/optimized_sampling.py)，当前标识 `query-event-scheme4-v3.1`。原版③、原版④、过渡版及原有按帧新版④均保留；新方案不改日常默认入口，不覆盖 r4 冻结源码或既有结果。当前共保留五种实验路线。

已落实的行为：

- 问题驱动深度分配：`direct / entity / event / causal`。已读 summary 足以回答时可跳过建图；只对当前需要的属性、事件角色、状态变化或原因做增量抽取。深度提升后不在本题内降级。
- 批量规划：默认最多 4 次规划、初读 6 条 summary，后续每批最多新增 8 条；按场景分组，每个抽取批次最多 6 条来源、3 个实体。规划后执行一批读证据及必要抽取，不为每个代表帧重新规划。精确证据/字段请求缓存与无新增证据停止条件防止重复工作；这些数值是待验证参数。
- 来源位置绑定：程序为当前批次的原始文本生成短语引用表（单个引用最多四个本地词元），模型只选择 `span_id`，不自行计算下标或重新生成事实文字；程序恢复实体名、属性值、谓词、动作及原文位置，时间及状态全文由原始来源回填。已有局部实体的引用候选在解码 schema 中绑定其固定原文名称。新实体由第一条引用锚定，名称不同的附加提及及依赖它的观测隔离记录，不能合并成同一个实体。必需实体/来源错误原子拒绝并有限重试；合法来源下的可选属性、原因、关系或事件语义错误隔离到 `rejected_fields`，不写入事实。外来来源 ID 仍是硬错误。引用合法只证明文字来源，不能自动证明属性归属或关系方向语义正确。
- 三类连接分工：时间/归属结构由目录提供；文本词项到来源的轻量倒排索引用于候选检索，尚不是完整 NER 或物理实体识别；语义实体/事件按问题抽取。检索在簇外、簇内都结合原问题与当前缺口的视觉及文本得分。动作、顺序和变化围绕问题相关锚点扩展短窗口，可跨相邻场景但受场景数和读取预算约束。
- 重复事件与持续状态分开：事件保留独立动作锚点、角色、来源、时间界限和证据类型；同一 summary 内不同动作位置也可分成不同实例。相同端点/谓词的不同时间关系保留独立来源记录，只对相邻支持的持续关系做投影压缩；不跨未知空档补持续状态。“回到旧状态”仍为新实例。事件与前后状态的时间候选关联明确标记为非因果证明。
- 稀疏出现索引：已关联实体指向局部实体/场景/来源列表，场景有反向索引，不展开所有场景对。跨场景身份只在规划明确要求时核验，单次最多筛选三对；按双方来源、验证范围与身份修订版本缓存。局部实体保留，身份关联可以撤销后重建投影，竞争的同场景实例不得因多次成对调用被静默合并。
- 来源与不确定性保持：summary 明确陈述标记为 `caption_asserted`；仅由前后持有推断的转移事件保持未解决假设。只有当前题实际已读的来源及身份依据进入模型上下文。序数/计数/最后一次问题保守要求穷尽来源覆盖；范围未覆盖和请求的事件/因果结构未建立时明确记录。读取全部 summary 仍不能证明描述没有漏掉真实事件，仍须结合问题核对事件完整性和必要像素证据。
- 同证据消融：优化版完成回答后，额外对完全相同的已选原始 summary、同一选项和可选视觉补充做一次不带实体/事件记忆的 QA。该对照属于记忆及其证据说明这一整体包的作用检查，不能单独归因于一个字段；额外调用预算和成本独立记录，不作为优化版线上耗时。

### 4.5 分析约束解码、前缀缓存与批处理

先细分计时：

- 模型加载与冷启动。
- 输入编码、prefill。
- schema 构建、编译与逐 token 合法集合计算。
- GPU 逐 token 生成。
- 来源/语义校验、重新生成与落盘。

随后在固定模型、精度、输入输出约束下比较现有后端与候选引擎。语法有效不等于来源正确，来源和语义校验仍需保留。

分页时尽量使固定指令、字幕与来源 ID 构成稳定公共前缀，把页码、已有实体进度置于变化部分；缓存键须包含相关输入与模型、提示、schema 版本。

批处理主要测试不同视频的独立请求，分别报告吞吐量和单题延迟。同一场景分页、后续导航存在依赖，不应为了并发而重排会改变语义的步骤。

## 5. 实验顺序与验证指标

| 阶段 | 实验 | 主要判断 |
| --- | --- | --- |
| E0 | 固定证据的直接 QA / 当前记忆 / 精简记忆消融 | 实体记忆对最终回答是否有独立收益 |
| E1 | 短字段编码、引用回填分别测试及组合 | token 是否减少，能否恢复标准语义与来源 |
| E2 | 轻量实体候选加大模型复杂处理 | 成本下降与实体/状态召回的取舍 |
| E3 | 增加阶段计时，比较结构化生成引擎及缓存 | 耗时究竟来自生成、约束检查还是重复输入 |
| E4 | 独立测试按缺口选择抽取深度及导航 | 改变抽取范围后端到端准确率与覆盖是否可接受 |
| E5 | 扩展到完整固定题集 | 验证小样本结论及长尾耗时 |

初始固定 30～50 道开发题，覆盖场景长短、实体多寡、时序/跨场景需求，以及来源引用与未知身份等边界情况；按输入条件选题，不按某方案答对与否筛选。记录清单、输入哈希、源码、模型、提示和 schema 版本，避免边跑边改变统计范围。

至少报告：

- 同题准确率、逐题纠正/退步、运行错误与抽取不完整数量。
- 总墙钟、平均/中位数/P90、目录/抽取/导航/QA 各阶段耗时。
- 调用数、输入输出 token、重新生成、超时与失败的全部花费。
- 实体及必要状态的召回、来源正确性、关系方向、未知信息是否被错误确定。
- 峰值显存、GPU 型号与 UUID、共享负载、冷/热启动口径。

抽取质量应抽样人工核对原字幕，不能把旧模型输出直接作为金标准。小样本用于开发；选择方案后再在完整固定题集上复验，并明确开发集结果的性质。

涉及编码、回填和缓存的检查应覆盖引用越界、字段恢复、未知原因、同名不同实体、来源版本失效及修复分支。真实 GPU 测试同时检查标准网络与调用预算，不能只检查 JSON 能否解析。

所有新实验使用独立输出目录和冻结源码，保留原任务、已有结果和历史失败花费。
