# 从 VideoTree 到 SCRIPT 的逐步迁移实验

2026 年 10 月 17 日，新加坡时间。目标是识别哪些模块带来收益、哪些模块造成退步，而非一次更换多处后只比较总分。9 组均使用原固定 300 题、相同 Qwen2.5-VL-7B 权重、温度 0、最多 1024 输出 token。属于已有开发题组的探索性实验。

实验目录：[videotree-script-migration-300-20261018-r2](../../../../../../../../../../scratch/Projects/CFP-05/CFP05-CF-136/hli/workdirs/VideoAgent/videotree-script-migration-300-20261018-r2)。原常规读取实验已完成：171/300（57.0%），2 道失败保留计错；默认入口仍是修复后的 `coverage_first`。

## 分组与比较关系

主链为 `v0 → v1 → s2 → s3 → s4 → s5 → s6`；另设 `s3 → c8` 和以 `v0` 为保护基线的 `g7` 分支。每组完整分母为 300，共 2700 个阶段结果，不能当作 2700 个独立样本。

| 组 | 相邻对照 | 只替换的模块或证据条件 | 回答的问题 |
| --- | --- | --- | --- |
| v0 | 原始历史 VideoTree | 原树所选描述，原 QA 模板、A–E 顺序与原生成函数 | 扩展关闭时能否复现基线？ |
| v1 | v0 | 用全部原始秒级描述替换树筛选后的描述，QA 不变 | 多给描述是补充信息还是引入噪声？ |
| s2 | v1 | 换成 SCRIPT direct QA，保留原选项顺序 | SCRIPT 问答模块是否有损失？ |
| s3 | s2 | 内容哈希重排选项，再恢复原编号 | 重排的实际收益与代价是什么？ |
| s4 | s3 | 改成 SCRIPT 重叠窗口及场景摘要包装 | 窗口/剧本上下文组织是否有帮助？ |
| s5 | s4 | 加入上一轮真实少看流程留下的核验事实及其来源 | 少量视觉事实是否改善最终选择？ |
| s6 | s5 | 将少看事实换成同题常规读取的核验事实 | 更多事实带来额外收益还是干扰？ |
| g7 | s5，并同时比较 v0 | 没有新增区分证据时保留 v0；改变答案须经独立审核 | 保基线规则能保住多少旧对题、错过多少修正？ |
| c8 | s3 | 换成联合“描述初判＋是否核查”的模块，记录计划但不执行 | 新联合控制器是否导致提前停止或问答退步？ |

`s2` 改的是完整 QA 接口，包括指令、表示和约束解码，不能将其差异单独归因于 JSON。`s4` 测试窗口/场景包装这个整体，也不是只测窗口重叠。`c8` 是单次决策模块回放，不等同完整少看在线流程。

## 为什么先固定证据

这批阶段执行新的模型问答，但树、原始 caption 和视觉观察均固定。视觉事实来自已完成的 `script-badcase-repair-300-20261017-r2`：两组当时共享相同 M0，所有事实均来自真实运行。未重新观看视频或重做核验，且不按本次正确答案选择事实。

这样可以先区分“原来取到的证据有没有帮助”和“最终回答是否误用证据”，避免两组碰巧读到不同画面掩盖 QA、排序、表示的影响。`s4–s6` 使用统一的需求/停止脚手架，只更换事实和来源，因此属于模块隔离实验，不要求其结果等于历史整套 SCRIPT。

已完成的新少看在线结果（142/300，47.33%）和常规在线结果（171/300，57.0%），另列为 `online_controls`，保留端到端参考，但不把它们当作相邻单模块因果对照。后续应把本批确认有收益的组合再放回在线取证流程验证。

## 基线兼容性验收

- 对原 VideoTree 299 个成功样本，重建 QA 输入，并已逐字节对齐原 system 与 user 提示。原有格式细节不擅自清理。
- 原先 1 道缺少树/QA 的失败题仍在 v0 的 300 题分母中计错，其他阶段可使用已有完整描述作答。
- 后台先对 2 题完整重跑原版宽度扩展、深度扩展和 QA，复用原帧特征缓存，检查节点索引、提示和预测与历史一致。
- 随后对 8 题运行全部阶段；v0 还检查预测与输入 token 数。兼容性或运行边界失败则不释放完整 300 题阶段。
- 关闭扩展时只走原 QA 生成路径；没有区分事实时 g7 不再调用模型，直接保留基线。对应 CPU 检查已通过。

300 个推理输入包已检查不含答案、正确性或历史预测字段。标注和历史预测只在独立评分及完成后的兼容性比较中读取。286 个历史少看首轮输入与 c8 输入的值和序列化结果完全一致，有助于直接诊断该模块的行为。

## 答案保护规则

g7 以 v0 为基线、s5 为候选。若候选不变或没有候选，保留基线。先从带视觉来源的已支持事实中筛选与两选项区别相关的信息，排除推断和已知单帧动态动作绕过状态类型检查的情况；再由独立文本审核判断事实是否直接解决区别。审核须引用新事实的合法 ID。

共同动作、没有看见、泛化目的和审核失败均不能单独触发答案修改。词汇筛选及语义审核仍是待验证的方法，不能保证真实语义判断正确或准确率只升不降。记录候选答案、采纳情况、审核失败及被修对/改错的题，避免只报净增益。

## 成本与结果口径

每阶段回放使用 600 秒账本；保留原模块的调用额度和解码约束。模型/约束器初始化另记为共享 setup 成本。报告实际回放耗时、独立执行所需的 QA 耗时、输入 token 数、描述省略情况，以及原取证过程的历史耗时。

**回放时间不等于端到端在线时间。** 原视觉取证成本没有重新测量；历史取证耗时不与新 QA 耗时混在一起冒充实测。相同输入的无事实阶段直接复用相同答案，记录实际零新增调用和独立执行成本。固定顺序、共享模型和缓存也会影响微小耗时差异。

`comparison.json` 保存各组完成数、错误、完整准确率和相邻配对结果。错误保留计错，没跑完时准确率为 null。每条比较包含修对/改错 ID、净正确题变化、完整准确率差及未校正的配对精确检验；多组探索及开发集复用不支持直接宣称泛化收益。
