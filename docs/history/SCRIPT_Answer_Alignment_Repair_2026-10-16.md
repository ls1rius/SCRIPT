原提示词要求先生成选项编号，再生成解释；这给先选后解释留下了空间。这是需要改进的设计，尚不能仅凭这些案例证明它是全部错误的唯一原因。原 gate 也发生过所有选项都被判为支持的情况，因此不能简单再相信一次相同的 gate。

这次改动包含：

1. 在同一次最终回答中，先生成最多 160 字符的证据摘要，再逐项比较，最后输出编号。
2. 每项检查必须说明关键区别，并区分“与证据吻合”“只看到了共有步骤”“有正面冲突证据”“未知”。没有观察到不能算反证，共有的后续步骤不能推出独有的前序动作。
3. 如果逐项判断恰好只有一个吻合项，但最终编号选了其他项，程序纠正编号，保存原编号与纠正记录，并替换对应的解释和引用。多项吻合或没有吻合项时，不强造唯一支持。
4. 保留现有停止状态规则：逐项比较不产生新事实，也不把证据不足升级为充分。与 gate 候选不一致时，仍按已有规则降为不足。

仍使用一次最终回答调用，模型、最多 1024 个输出 token、30 秒最终生成预留、取证轮数和原始观察均保持原配置。输出内容增加，实际生成耗时是否增加、增加多少，需要回放测量。

## 后续补充：让观察结果保留选项需要的区别（V10）

V9 的 294 题实验只替换最终回答，继续保留其冻结版本。V10 在此基础上修复观察输入与缺口反馈：

- 将原问题、全部候选选项、检查目标传给直接观察和实体关系提取模块。模型视图展示每个候选的文本区别，观察契约要求优先记录工具、行动者左右手、准备步骤、交接与时间顺序；候选内容不代表已经发生。
- 视觉核验模块不接收选项，仍独立检查候选事实及其源帧、过程可见性。要求将复合动作拆成独立事实，能确认的部分分别保留，不能确认的部分报告为缺口。
- 原先输出后被丢弃的观察不确定性，现在带原视频区间保存，送入下一轮规划、观察、语义核验和最终回答。它不能被当作反证或其他查询的事实，也不自动阻止后续有效证据消解缺口。
- 缓存键包含观察目标、问题、候选和检查项。更换细节目标后重新提取；完全相同的请求仍可复用结果与缺口记录。

这是一次明确的实验条件变化：观察模型现在可见全部候选；检索入口配置不变。未增加预算或任务轮数，实际 token、取证调用数和耗时仍需运行后统计。

全套 **175 项 CPU 测试通过**，包括观察/提取的实际调用边界、独立核验输入、缓存失效与复用、带时间的缺口反馈、查询隔离，以及诊断任务的原始 M0 复用和纠正/改错双向统计。原有一项要求观察阶段不接收选项的测试，按新设计改为检查全部候选被传入，同时继续检查概括题不重复生成目标。
