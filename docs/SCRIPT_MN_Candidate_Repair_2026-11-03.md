## 当前实现

共享模块 `script_core/m_candidate_selection.py`。M 与 N 调用同一个选择器，N 保留其独立缓存及已有角色抽取/原文保留逻辑；此次未把 N 的来源抽取改动迁回 M。

1. 问题与全部选项进入一次检索规划。每个选项均须分别列出可观察事实和推测目的，不把任何候选答案设为问题前提。
2. 原始全部场景摘要、问题、全部选项和规划进入一次候选判断。每个场景必须输出该场景内的字面原文引用（或 null）及证据等级。引用受逐场景枚举约束，不能改写或串用其他场景内容。
3. 程序将具体任务证据/相关背景/无关映射为 100/50/0，按降序及原目录同分顺序生成闭合队列。正分必须有引用，无关场景可保持空候选；不要求数量或时间覆盖。等级是模型判断，不是概率。
4. 后续沿用 M 的顺序读取、缺口检查、充分即停及候选耗尽即停。最终答案仍由原模型生成。

初筛固定两次生成调用。相比逐场景逐选项的诊断减少调用次数，但实际耗时受输入长度及 GPU 共享影响，不作受控速度结论。原文引用与模型等级是实际筛选依据；程序保存其映射规则，不事后编造自然语言理由。全部原始调用、检索规划、候选提议、执行队列和后续逐轮导航继续落盘。
