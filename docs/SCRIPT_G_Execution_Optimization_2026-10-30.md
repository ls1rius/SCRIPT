# G 独立执行优化

2026-10-30，新加坡时间。该优化延续 G 的结构和抽取方法，不新增算法组编号。

## 范围与产物

用户要求另行优化，并允许有足够空闲显存时共享 GPU。原 G 正式评测
`workdirs/generalized-entities-G-300-20261030-r3/` 保持运行；不替换其源码、预测或结果。

执行模块是 `script_core/generalized_execution.py`，独立验证入口是
`script/benchmark_generalized_execution.py`。当前验证目录为
`workdirs/G-execution-batch-20261030-r2/`，控制器会在任一卡连续三次观测到至少
32768 MiB 空闲后加载模型，不要求整卡空闲，不停止已有进程。

首轮 r1 在模型加载前发现通用加载器依赖 F 专属模块，已停止。r2 使用 G 独立加载器；
r1 的异常、报告和费用记录保留，并由 r2 的 `experiment.json` 引用。r2 于 20:47
在 GPU 3 启动真实对照验证，21:11 全部完成，退出码为 0。

## 执行行为

- 比较原冻结串行调用、两条独立输入组成的 batch、四条独立输入组成的 batch。
- 每条来源独立保留提示词、原文词表、JSON schema 和解码器；不把多句合入同一个提示词。
- 保留 G 的开放状态、八类属性、动作角色、未知执行者规则、来源校验和原文保留。
- 初次抽取后按原规则识别被拒收的动作，最多再做一次同源完整角色复核；不减少复核，不局部补写。
- 保留相同模型快照、bfloat16 精度、贪心生成和 1536 token 输出上限。
- 模型批次失败即停止该验证；不自动重试、拆批或切换串行重跑。无效来源输出显式记错并保留原文。
- 每批初次抽取和复核只计一次时间。初始化、预热、失败以及此前尝试分别记账。

公共提示词 KV 缓存暂未实现。Qwen-VL 的位置编码、前缀边界及可变缓存隔离需要单独验证，
不能直接复用上一来源的生成缓存。提示词缩短、JSON 字段缩写和复核策略调整不属于当前实现。

## 验证与解释边界

CPU 检查包含提示词与原路径一致性、来源词表隔离、否定/不确定保护、完整角色复核、
失败不重试、参考目录不写入，以及真实 Transformers 模型与 LMFE 的独立批量解码。
连同 G 既有结构及实验入口检查，共 29 项通过。

真实样本固定取前八个已完成 G 问题，按来源顺序轮流选择 64 条，不读取问题答案或正确率；
另重放原 G 的 14 条功能来源，共 78 条。功能来源覆盖开放状态、未知执行者、否定、属性、
关系及多个动作。先检查原串行路径与新执行器 batch size 1 的输出和输入 token 数一致，
再交错执行串行、batch 2、batch 4，以轮换顺序减小时间段负载偏差。

报告逐条比较完整接收结果、事实、复核标记、原文保留和错误，并保留不同来源 ID。
这项验证测的是来源抽取及复核，尚未新增最终 QA 答案，也没有测量问答准确率变化。
有限样本一致不代表全量逐字一致；共享 GPU 的时间比值只作观测结果，不作受控算法加速比。

采用优化版本前应检查输出差异。当前实现没有自动接入原 G 评测或默认 D 查询路径。

## 真实验证结果

78 条来源均完成，三种执行方式都没有来源错误或失败批次，各执行了 107 个来源请求，
含 30 次角色复核；另有一条否定来源直接保留原文，不调用模型。

| 执行方式 | 抽取及复核总秒数 | 平均秒/来源 | 相对串行观测速度 | 完整来源结果与串行不同 |
| --- | ---: | ---: | ---: | ---: |
| 串行 | 534.27 | 6.85 | 1.00 | 0/78 |
| batch 2 | 445.40 | 5.71 | 1.20 | 3/78 |
| batch 4 | 343.97 | 4.41 | 1.55 | 5/78 |

14 条功能来源的三种结果均一致，差异出现在其余真实描述。完整来源结果的比较包含接收事实、
实体提及、拒收记录、不确定标记及原文保留决定，不能把全部差异都解释为事实内容变化。
其中确有事实变化：`R0036` 的 batch 2/4 都遗漏串行输出的 `phone on table` 空间关系；
`R0038` 的执行者从 `K` 变为 `woman K`，整句原文保留决定也随之改变。
其余差异包含不确定标记和拒收理由变化。全部逐条结果保存在 `results/`，模型输入输出保存在 `calls/`。

原冻结串行路径的 78 个来源结果与历史捕获结果全部一致；有模型调用的 77 条来源初始输入
token 数在各执行方式间均一致。`validation/reference_unchanged.json` 确认原 G 冻结文件未变。
初始化 41.04 秒、预热 21.69 秒单列，总计已测量 1386.36 秒。

结论：批量执行在本次共享环境中提高了吞吐，但没有通过样本输出完全一致检查。
暂不接入原 G，尚无批量版本最终问答准确率结果；上述时间比值不能外推为独占 GPU 加速比。

## 使用

```bash
/mnt/ssd2/hli/work/miniconda3/envs/vts/bin/python script/benchmark_generalized_execution.py prepare \
  --reference workdirs/generalized-entities-G-300-20261030-r3 \
  --out workdirs/G-execution-batch-NEW --questions 8 --sources 64
/mnt/ssd2/hli/work/miniconda3/envs/vts/bin/python \
  workdirs/G-execution-batch-NEW/control/benchmark_generalized_execution.py queue \
  --out workdirs/G-execution-batch-NEW
```

准备必须使用新目录；失败重开时可用 `--prior-attempt` 引用已停止且记录完整的上一尝试。
每份运行目录都保存独立冻结源码、请求、配置、hash、原始模型输出、来源结果和费用记录。
